# apb 1.0.0-beta.6

The sixth beta of apb 1.0 makes playbooks check their own work and lets a
run teach the next one: typed node outputs and write scopes hold an agent
to its contract, loops end when reviewers stop finding new items, a
routine reads its previous successful run, and what people correct, what
fails and what happens after a run ends are kept and shown across runs.

## Installing the beta

1.0.0-beta.6 is published as a GitHub pre-release. The `latest` release and
the Homebrew formula stay on 0.25.0, and `apb self-update` of a stable
install stays on the stable line. A beta install from beta.4 on reaches this
one with `apb self-update`; an earlier beta uses the installer below.

Shell installer for this tag (macOS, Linux x86_64):

```sh
curl --proto '=https' --tlsv1.2 -LsSf https://github.com/itechmeat/agentic-playbooks/releases/download/v1.0.0-beta.6/apb-installer.sh | sh
```

## Run feedback that outlives the run

1. Scenario capture. `apb scenario capture <run-id> --name <slug>` turns
   a finished run's journal into a regression scenario that replays its
   answers, scrubbed and redacted. It previews first and writes only on a
   second act of a person bound to the previewed digest
   (`stale_preview` otherwise), and never replaces a file
   (`scenario_exists`). MCP `run_scenario_capture` and
   `POST /api/runs/{id}/scenario-capture` only preview; the dashboard's
   run page saves. What the scenario format cannot replay exactly (list
   nodes, host mode, supervisor directives that move a run, interrupted
   attempts and more) is refused with every gap named. Scenarios gain a
   scripted timeout, `timed_out: true` on an attempt answer. Details in
   `docs/EVALS.md`.
2. Corrections ledger. Every run end adds what people corrected (a review
   note, a note posted to a node, an answer to a question) and apb's own
   rejections of a claimed success to the playbook's signed, scrubbed
   ledger (`.apb/corrections/<scope>/<id>.json`). Entries are grouped
   without a model; one that recurs in two runs is `proposed` with a draft
   prompt line. apb never applies the draft: a person adds it and marks the
   version that carries it (`apb corrections <playbook> fixed <entry>
   --version X.Y.Z`), and the entry is `reopened` when its rate on that
   version does not fall. Shown to people only: `apb corrections`, MCP
   `playbook_corrections` and `correction_decide`, and the dashboard;
   every entry point is refused from a run step. Details in
   `docs/CORRECTIONS.md`.
3. Follow-up check. `follow_up: { after, grace?, check }` reads one check
   in the baseline check's shape once `after` a successful run end, by a
   detached waker or by `apb resume --all` when the machine was off, and
   journals `follow_up_observed` with `met`, `not_met`, `unknown` or
   `missed`. It shows in the run outcome (`not_met` needs a look), in
   `apb stats` and through the opt-in notification transition
   `follow_up`. Validator codes V183 to V186. Details in
   `docs/HOWTO-authoring.md` ("follow_up").

## Recurring routines

1. `run.previous_success`: a prompt can read the id, times and chosen
   outputs of the latest earlier successful run of the same playbook in
   the same scope, with a `when_none` block for the first run. The values
   are looked up once at start, redacted and journaled, so a resume
   renders the same. Validator code V176.
2. Param patterns: `pattern` on a text param, matched whole; every launch
   surface refuses a value that does not match
   (`param_pattern_mismatch`, never naming the value). Validator codes
   V177, V178.
3. Untrusted input: `untrusted` on params, connector bindings and nodes,
   and `accept_untrusted` with a reason on an agent. The validator follows
   the text to every agent that renders it and refuses one that can send
   outward without an accepted reason (V179 to V182); such an agent gets a
   fixed `## untrusted input` section as the last text of its prompt.

## Node contracts

1. Typed and required output fields (`{ name, type, values, required }`):
   a mismatch rejects the attempt and the retry briefing names it. V167,
   V168.
2. Numeric thresholds on `output_field` edges: `lt`, `lte`, `gt`, `gte`.
   V169.
3. Write scope: `writes` and `max_changed_files` on agent and script
   nodes, checked after every attempt; a violation fails the node. V170 to
   V172.
4. A check that must fail first: `success_check { script,
   prove_fails_first, on_green_before }`, journaled as `check_proved`.
   V173.
5. Stall exit: with `stall_after: N` a node stops retrying once the same
   rejection repeats N times and ends `stalled`, with an opt-in `stalled`
   notification. V174, V175.

## Loops and graphs that check themselves

1. Templates render an array or object field as compact JSON, so fix nodes
   get the reviewers' findings.
2. Read-only nodes may share a concurrent batch with other read-only
   nodes, never with a writer; bundled reviewers that run no commands are
   `read_only`.
3. The edge condition `no_new_items` and the `{{nodes.<id>.seen.<field>}}`
   template end an open-ended loop when rounds stop finding new items.
   V164 to V166.
4. A rejected success report carries apb's reason (`rejected_for`); the
   retry briefing quotes it with a repair-scope paragraph.
5. Scenarios: `expect.status` checks a node's recorded status.

## Other changes

1. The bundled `apb-brainstorm` skill (1.2.0) adds a builder check for
   risky designs and a short record for a fully specified request; the
   `apb-delivery` skill and the `apb-feature-delivery` playbook accept it.
   Bundled `apb-feature-delivery` and `apb-code-review` declare typed
   reviewer fields, and `apb-issue-triage` and `apb-inbox-digest` mark
   their outside text as untrusted.
2. The rule that a dashboard without keys takes no publish consent lives
   once in the engine, and next actions mark it `keyless_dashboard`.
3. The daily cleanup keeps a merged worktree whose busy lock is parked by
   a run only while that run is still paused.
4. `.apb/handoff/` and `.apb/corrections/` are git-ignored.
5. The dashboard's connector editor keeps `on_unknown` and `untrusted`
   when it saves a binding.

## Behaviour changes

1. A bundled reviewer that writes to a tracked file now fails at once and
   its change stays in the tree, where it used to be undone and retried.
2. A typed output field that does not match its declaration now rejects
   the attempt, where it used to pass.
3. A playbook with `follow_up` leaves a sleeping `apb __pause-waker`
   process after a successful run, and `apb resume --all` also reads due
   follow-ups.
4. Every run end of a playbook whose runs carry corrections writes
   `.apb/corrections/`.

## Compatibility

1. Journal: new events `check_proved` (not a checkpoint, older readers
   skip it) and `follow_up_observed` (a checkpoint, appended only after a
   succeeded `run_finished`); additive fields
   `read_only_violated.concurrent_with`, `attempt_finished.rejected_for`,
   `attempt_finished.rejection_fingerprint` and `attempt_finished.stalled`.
2. An apb older than this release refuses to resume or continue a run
   that has a `follow_up_observed`; its read-only surfaces skip and count
   the event, and its stop path allows it.
3. New run guards `write_scope`, `previous_success` and `untrusted_input`:
   an older apb refuses to continue a run that uses them. A fresh launch
   by an older apb drops the unknown keys and runs without them.
4. A scenario answer with `timed_out: false` is left out of the
   serialized form, so every existing scenario keeps its digest.
5. The known problems store now goes through a shared signed store; files
   written by an earlier release still verify.

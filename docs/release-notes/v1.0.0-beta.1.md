# apb 1.0.0-beta.1

The first beta of apb 1.0. The playbook schema and the CLI in this release
are the ones 1.0 intends to keep. It is still a beta, so the schema, the CLI
and the MCP surface may change before 1.0.0 where feedback shows a problem.
Reports and feedback are welcome in the issue tracker.

This release carries everything merged since 0.25.0, including the join fix
drafted as 0.25.1, which was never tagged.

## Installing the beta

1.0.0-beta.1 is published as a GitHub pre-release. The `latest` release, the
Homebrew formula and `apb self-update` stay on 0.25.0, so existing installs
are not moved to the beta.

Shell installer for this tag (macOS, Linux x86_64):

```sh
curl --proto '=https' --tlsv1.2 -LsSf https://github.com/itechmeat/agentic-playbooks/releases/download/v1.0.0-beta.1/apb-installer.sh | sh
```

From source (see `docs/INSTALL.md`, section 5; `cargo install --git` is not
supported because the web frontend must be built first):

```sh
git clone --branch v1.0.0-beta.1 https://github.com/itechmeat/agentic-playbooks && cd agentic-playbooks
(cd web && bun install && bun run build)
cargo install --path crates/apb-cli
```

The archives on the release page can also be downloaded and verified by hand
as described in `docs/INSTALL.md`, section 4. To go back to the stable line,
run the `latest` installer from `docs/INSTALL.md` again. Read the journal
compatibility section below before driving an existing run with an older
binary.

## Run outcome and reliability

- **An honest run outcome.** `run_report`, `apb runs <id>`, the API and the
  dashboard show what was done, how it was verified (goal criteria, success
  checks, baseline), what was not verified (manual criteria, self-reported
  steps, writes with an unknown effect, cut responses, inbox gaps, truncated
  output, unknown baseline reads), findings and warnings. `runs_list`,
  `apb runs` and the run list show a needs-a-look marker.
- **Baseline checks.** A playbook may declare `baseline_check`: read-only
  checks taken before the first node that acts and again after the last
  action, with typed observations and an explicit rule. Sources are a
  read-only connector function, a script under `scripts/`, or
  `project_checks`, which discovers the project's own test, lint and check
  commands and holds the rule "no new failures". A read that cannot be
  trusted is `unknown`, never zero; with `enforce: true` a not met or unknown
  comparison fails a run that would otherwise succeed.
- **Findings and warnings.** Agents may report bounded `findings` and
  `warnings` in the status file or with a host submission. They are
  journaled as `attempt_notes` and never change a verdict, a route or the
  run. `apb stats` groups findings by kind and location across runs.
- **Honest connector results.** A read-only function whose response was cut
  at the cap or failed mid-read returns `incomplete_response` instead of a
  partial success. A function that may have changed the world stays a
  success but reports `effect: committed` and `response_complete: false`.
- **Inbox gaps.** A read whose cursor fell behind inbox retention returns a
  `gap`, journals `inbox_gap`, and the run surfaces say which unread events
  were dropped.
- **Bounded agent output.** Agent stdout and stderr are kept as a bounded
  head and tail with a count of the dropped bytes; log files and transcripts
  stop at a cap. Limits live in the new `output_limits` config section
  (2 MiB head, 6 MiB tail, 64 MiB per file by default); a project may only
  lower them. When output was cut and the agent's final record is missing,
  the attempt fails as incomplete output.
- **Graceful timeout.** A timeout stops the agent through the same path as
  `pause --now`: SIGTERM, a grace period (`APB_TIMEOUT_GRACE_MS`, default
  5000), then SIGKILL.
- **Text modes.** Connector functions may declare `text_args` with
  `markdown`, `markdown_no_commands` or `literal` per string argument. The
  official gitlab connector (0.2.0) escapes slash commands in comment bodies
  and descriptions.
- **Joins wait for a re-run branch** (#203). `apb resume --from-node` and a
  supervisor retry, continue-from, patch or move off a review gate no longer
  start a join whose other branch the re-run brings back to life, and a run
  no longer ends through a join's old route before the join ran on the new
  input. The re-run node and everything only downstream of it read as not
  yet run until they run again; an automatic restart of interrupted work
  revives nothing.
- **Joins inside loops** weigh each round on their own, a finish node with
  two inputs no longer waits for a bounded edge its source already used up,
  and a strict journal read that meets a torn last line reads once more
  under the append lock instead of failing the run.

## Lists and send-once

- **List mode.** An `agent_task` or `script` node may declare `list:` to run
  once per item of a JSON array (an earlier node's output field, a filtered
  list node's items, or inline items). Items are validated before any work
  (unique safe ids, `max_items` default 100 and hard cap 500, 8 KiB per
  item), run in batches, and each is checked right after it finishes by an
  output field, a script, a read-only connector function or a judge. Only
  rejected items run again; an item whose retries are spent or whose check
  cannot tell needs a look. Pause, quota pause, crash and resume continue
  with the unfinished items only.
- **List surfaces.** The run outcome has a line per list, `run_status` and
  `run_report` carry item counts and items, `apb runs <id> --items` prints
  one line per item, and the dashboard has a list panel with a filterable
  item table.
- **Send once.** A connector send function may declare `idempotency`: `key`
  (a nonce in a header or body field the service dedupes on), `marker` (a
  hidden marker reconciled against recent items of the connector's own
  account) or `none`. Before a declared send apb journals a durable intent
  and settles it after; a repeat of the same intent gets the earlier result,
  a reconciliation or a refusal. With `key`, a send whose outcome is unknown
  may be replayed with the same key inside the service's dedupe window,
  where the service drops the duplicate. Any other unknown outcome is never
  resent automatically unless the binding says `on_unknown: resend`; a
  person settles it with `apb intent resolve` or the MCP tool
  `run_intent_resolve`.
- **Attempt memory.** Connector calls are bound to the attempt that made
  them, and a retry, fallback, continuation or resume gets a briefing of
  what earlier attempts sent, what has an unknown outcome and what did not go
  out.
- **Apb-Run trailers.** Commits a node made are reported with their
  `Apb-Run` trailer state. Existing commits are never rewritten.
- New examples: `review-panel`, `review-panel-list`, `inbox-triage`,
  `bulk-reminders`, `crm-cleanup` and `dependency-security-fix`.

## Environment and secrets

- **Process environment by allowlist** (opt-in per profile).
  `process_env: { policy: allowlist, allow: [...] }` starts the agent from an
  empty environment plus a base set, the agent's own variables and the
  profile's `allow` names or `PREFIX*` patterns. Connector variables are
  always withheld. The policy is snapshotted in the run manifest, and
  `agent_env_applied` journals counts and names, never values.
- On Linux apb marks itself non-dumpable before the first allowlisted spawn.
- **Sealed secrets.** Resolved secrets are a sealed type: printed as `***`,
  not serializable, compared in constant time. Text that comes back from a
  connector call has every resolved value redacted, also in its
  percent-encoded and Basic auth forms.

## Time and cost

- **Estimate before a start.** apb estimates time, tokens and cost from
  comparable past runs (same version and execution mode, per node the same
  profile digest), each figure with its spread and the number of runs behind
  it. `apb run --estimate` shows it without starting; `playbook_run`,
  `playbook_prepare_run`, the API and the run dialog show it too.
- **Run budget.** `budget: { tokens, usd, on_no_estimate }` in the playbook
  or per run is a predictive stop between steps, not a ceiling: when the
  remainder is below the next step's median, the run drain-pauses. A budget
  pause is resumed only with a decision (raise, new limit, new policy, or let
  the paused step run once).
- `apb stats` groups each node by profile and skill digest when they changed
  within a version.

## One playbook, many places

- **Fit report.** One report of a playbook against a workspace in four
  sections (compatibility, setup, trust, consent), behind the catalog
  `fit: true` summary, `playbook_adopt_report`, `apb adopt --scope`,
  `GET /api/playbooks/{id}/fit` and a dashboard card.
- **Remembered input.** Params and the instruction can be remembered per
  project (`apb run --remember`, `playbook_run.remember`, `apb memory`, the
  Run dialog), bound to the params schema digest. Secret params and
  credential-shaped values are never stored.
- **Import preview.** `apb import --preview` shows definition and script
  changes before anything is written; `--accept` takes the bundle digest.
  Imported scripts need approval by digest on every surface.
- **Make global.** `apb make-global` and MCP `playbook_make_global` copy a
  project playbook with its profiles and remembered input to the global
  store, with a dry-run plan and undo on a failed step.
- **Bundles with scripts.** `apb export` writes bundle format 2, which
  carries the version's `scripts/` files.

## Messages to people

- **Run notifications.** A run can tell a person when it waits for a review,
  asks a question, is paused by the engine or a supervisor, or finishes. The
  target lives in the machine config; a project can only turn notifications
  off or narrow them, and only a person sets a target. Sends go through the
  send-once ledger, so a restarted driver never sends twice. `apb run
  --notify`, `apb notify <run>`, `apb notify test`, MCP `run_notify` and a
  dashboard control. Details in `docs/NOTIFY.md`.
- **Writing brief.** Text that people read (the finish answer, `agent_task`
  nodes with `audience: people`, nodes granted a function with a `people:`
  block) gets a short brief: conclusion first, who acts, facts, no internal
  terms, unverified claims marked.
- **HTML run report.** One self-contained page of the run outcome that
  opens from disk with no network and no script: `apb runs <id> --html <file|->`,
  MCP `run_report_html`, `GET /api/runs/{id}/report.html` and "Save report"
  in the dashboard.

## Quality and self-improvement

- **Run quality.** A `quality:` block grades a finished run: built-in
  criteria (outcome, loops, scope, consent, skill_use) graded by rules with
  no model call, and up to three criteria of the playbook's own, graded by
  the host agent through a bounded reading session that must cite what it
  read, or by a decision model (`quality.criteria_grader: model`,
  `apb grade --model`). Grades are write-once and signed. Details in
  `docs/QUALITY.md`.
- **Promotion by quality.** `promote_supervisor_patches` with
  `when: quality` promotes a candidate version only over comparable grades
  and only when no criterion is worse beyond the margin.
  `apb candidate <playbook>` and MCP `playbook_candidate`.
- **Known problems.** With a `known_problems:` block apb collects tool
  problems from earlier runs of the playbook, shows the significant ones to
  the agents as facts to check, and rechecks a problem when its source
  changed. `apb problems <playbook>`, MCP `playbook_known_problems`, a
  problems panel. Details in `docs/KNOWN-PROBLEMS.md`.
- **Repeats in history.** `apb discover` (MCP `playbook_discover`, a
  Discover page) reads local Claude Code and Codex session history, only when
  asked and only from named roots, and suggests draft playbooks for
  multi-step work that recurs. Nothing is sent anywhere and no model is
  called. Details in `docs/DISCOVER.md`.
- `apb stats`, the stats card and the HTML report show quality per version.

## Agents as modules

- Everything apb knows about an agent CLI lives in one module per agent,
  with a contract suite that runs every agent's scenarios through the real
  adapter against recorded fixtures.
- `apb doctor` checks each installed agent for free (its version against
  the verified one, the flags of the built-in forms in its help);
  `apb doctor --agents` covers all of them and
  `apb doctor --probe-agent <id>` makes one paid call to check the output
  format.
- On the stream transport apb compares the tools and MCP servers claude
  reports with what the node expects and journals `tool_exposure_mismatch`.
- Decision records live in `docs/adr/`.

## Isolation and publish

- **Enforced isolation on Linux.** `isolation` on an agent node is now a
  contract checked before every attempt: `full` refuses to start what the
  machine cannot enforce, `best_effort` runs with what can be enforced and
  journals the rest, `none` is unchanged. On Linux the sandbox is
  unprivileged bubblewrap; the agent sees only its tree, its agent home and
  the declared paths, cannot change the repository's git config or hooks,
  and with `network: none` gets loopback only. What is not separated is
  listed on every attempt and in `docs/ISOLATION.md`.
- **Hardened git.** Every git command apb runs pins the repository and
  disables hooks, fsmonitor, external diff and textconv programs, the
  repository's filter drivers, pagers, credential and askpass helpers and
  network transports, for every run, isolated or not.
- **Publish step.** A new node kind, `type: publish`, pushes the commits its
  source node made. apb pins the push URL, builds a read-only plan, and
  pushes only after consent to that exact plan (`apb publish
  show|approve|skip`, the dashboard publish panel, `review_decide` with the
  nonce). Over MCP apb cannot tell a person from the host agent, so the host
  must show the plan to the person before it passes the nonce. An unknown
  push result is never repeated by apb on its own. `publish_only: true`
  requires every agent, including those of sub-playbooks, to run with
  `isolation: full`, so an agent cannot reach the operator's push
  credentials. It does not sandbox script nodes, goal scripts or project
  checks, which run with the operator's credentials, and an agent with
  `network: open` can still reach endpoints that need no credentials.
  Details in `docs/PUBLISH.md`.

## Behaviour changes and upgrade notes

- **Validator.** New codes V62-V69, V84-V89, V93-V120. V68 reserves every
  node id that starts with `@` for engine sites. V16 (isolation declared but
  not enforced) is retired, its number stays reserved, and V112-V115 cover
  isolation instead. A list step may only grant write functions that declare
  idempotency (V88). `publish_only` without `isolation: full` everywhere is
  reported by V119.
- **Isolation is enforced.** A node with `isolation: full` now refuses to
  start on a machine that cannot enforce it, including every macOS machine;
  use `best_effort` where that is acceptable.
- **apb's own git is hardened.** Hooks, filter drivers, fsmonitor, external
  diff and textconv, pagers and credential helpers of the repository no
  longer run for the git commands apb itself runs.
- **Publishing playbooks ask for start consent** like any irreversible one,
  and no automatic decision ever approves a publish plan; a dashboard without
  keys can only show the plan and skip.
- **Slack and Zulip sends declare idempotency**, so a send with an unknown
  outcome is refused instead of resent. Discord sends use an enforced nonce
  and no longer allow mass mentions. GitHub `create_issue` and
  `comment_issue` use a marker; telegram, smtp and whatsapp declare `none`.
- **Unknown sends are not resent.** A declared send whose outcome is unknown
  waits for a person (`apb intent resolve`) unless the binding says
  `on_unknown: resend`; a `key` send may still be replayed with the same key
  inside the service's dedupe window.
- **Connector results.** A cut or failed read of a read-only function is now
  the error `incomplete_response`, not a partial success.
- **Timeouts** send SIGTERM and wait a grace period before SIGKILL.
- **Agent output** is bounded; an attempt whose output was cut and whose
  final record is missing fails as incomplete output.
- **cursor** always runs with `--output-format text`. **zcode** always gets an
  explicit effort (`low` when none is set), since without one it switches to
  its most expensive model, and a zcode plan written as `Account:` is checked
  like `account:`. The zcode fallback provider config moved into apb's state
  directory, and codex's stripped config is owner-only.
- **Writing brief.** The finish answer now gets the writing brief unless the
  finish node sets `audience: agents`; V101 warns about `audience` on a
  finish node without a prompt.
- **Imports.** `apb import` never approves an imported version
  automatically, imported scripts need approval by digest, and without a
  terminal an unaccepted import exits 3. Format 1 bundles still import.
- **Remembered input** replaces the instruction draft HTTP route with the
  memory route.
- **Capture scrubber.** Capture uses the shared stricter scrubber, which
  still refuses keyed values and long keys and no longer flags git hashes and
  UUIDs.
- **Profiles without `process_env`** keep their environment exactly as
  before; playbooks without `known_problems:`, `quality:`, `budget:` or
  `baseline_check` run as before.
- Dependencies were updated, including tokio, rustls-webpki, webpki-roots,
  webpki-root-certs and ctutils to versions that close the current RustSec
  advisories.

## Journal compatibility

New journal events: `baseline_observed`, `baseline_compared`,
`attempt_notes`, `inbox_gap`, `send_intent_recorded`, `send_intent_settled`,
`list_started`, `list_batch_started`, `list_item_settled`,
`agent_env_applied`, `budget_set`, `budget_gate`, `notify_set`,
`run_graded`, `candidate_held`, `known_problems_shown`,
`tool_exposure_mismatch`, `publish_target_pinned`, `publish_planned`,
`nodes_revived` and `join_input_revived`. New fields on existing events
(such as `item`, `output_truncated`, `transcript_incomplete`,
`response_complete` and who stopped a run on `run_aborted`) have defaults
and decode leniently.

Each new event is safe to skip up to the next checkpoint: an older apb that
reads a journal this release wrote skips the events it does not know while a
checkpoint follows them, and refuses to continue a run when one of them is
newer than the last checkpoint, with a message naming the version mismatch.

An older apb that resumes a run carries on without the features it does not
know. For example, it skips `budget_set`, so a run paused by its budget and
resumed with 0.25.0 continues without the predictive spend stop.

A run revived by a re-run (`nodes_revived`) must not be driven by 0.25.0 or
older: without that event an older apb routes the run the way 0.25.0 did,
which is the join bug fixed here, not a corrupt run. A run whose driver was
killed between the revival and the re-run node's finish must be resumed with
this release or newer. The reverse is safe: every node an older apb ran
leaves the revival on its own start or finish, so this release resuming
after it routes correctly.

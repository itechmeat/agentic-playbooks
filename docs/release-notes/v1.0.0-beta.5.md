# apb 1.0.0-beta.5

The fifth beta of apb 1.0 makes the decisions only a person may take hold
against a coding agent that runs as the same user: a person-only gate or an
approval is decided with a passkey, and a run that carries such gates can no
longer be resumed by an older apb past them.

## Installing the beta

1.0.0-beta.5 is published as a GitHub pre-release. The `latest` release and
the Homebrew formula stay on 0.25.0, and `apb self-update` of a stable
install stays on the stable line. A beta install from beta.4 on reaches this
one with `apb self-update`; an earlier beta uses the installer below.

Shell installer for this tag (macOS, Linux x86_64):

```sh
curl --proto '=https' --tlsv1.2 -LsSf https://github.com/itechmeat/agentic-playbooks/releases/download/v1.0.0-beta.5/apb-installer.sh | sh
```

## Older binaries refuse guarded runs

A run whose playbook has person-only gates or approvals records
`execution.mode: cli+guard` (or `host+guard`) in its manifest. Every apb
from 0.23 on refuses to resume such a run and says it was written by a
newer apb; it still reads and stops it. `apb runs`, `run_status` and the
run page show the base mode with a guard attribute. An apb older than 0.23
does not read the execution block, so every apb on a machine that runs
these playbooks must be this release or newer; `apb doctor` warns about
other `apb` binaries on `PATH`. A supervisor patch that adds a person-only
gate to a running run journals the guard but cannot rewrite the manifest,
so for that run the older stop-then-resume limit stays open.

## Fixes

- A run whose own `run.yaml` does not parse withholds its text as
  `[secrets_unresolved]` and names the config error, instead of printing
  text that might hold a declared secret. The runs list shows the row with
  the error and keeps the other runs readable.
- Review leftovers from #255 to #261 (#264): evidence sessions show while
  their attempt runs, an unknown project directory is marked as such, and
  smaller fixes in result capture, citations, run search, interventions,
  stats, the project registry, the report graph and the daily cleanup.

## Compatibility

- `execution.mode` in a new run's manifest may carry a `+guard` suffix;
  readers of this release report the base mode with `guarded: true`.

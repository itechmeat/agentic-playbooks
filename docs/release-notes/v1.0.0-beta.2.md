# apb 1.0.0-beta.2

The second beta of apb 1.0, with a new look for the dashboard. Every page now
uses one dark, terminal-style design built on the same shadcn-svelte
components: a monospace UI font, flat panels with thin colored borders, one
color per profile across the graph and the lists, and a status bar at the
bottom of each page. The playbook schema, the CLI and the journal are the
same as in 1.0.0-beta.1; the run and playbook listings gain a few fields
(see Compatibility).

## Installing the beta

1.0.0-beta.2 is published as a GitHub pre-release. The `latest` release, the
Homebrew formula and `apb self-update` stay on 0.25.0, so existing installs
are not moved to the beta.

Shell installer for this tag (macOS, Linux x86_64):

```sh
curl --proto '=https' --tlsv1.2 -LsSf https://github.com/itechmeat/agentic-playbooks/releases/download/v1.0.0-beta.2/apb-installer.sh | sh
```

From source (see `docs/INSTALL.md`, section 5; `cargo install --git` is not
supported because the web frontend must be built first):

```sh
git clone --branch v1.0.0-beta.2 https://github.com/itechmeat/agentic-playbooks && cd agentic-playbooks
(cd web && bun install && bun run build)
cargo install --path crates/apb-cli
```

The archives on the release page can also be downloaded and verified by hand
as described in `docs/INSTALL.md`, section 4. To go back to the stable line,
run the `latest` installer from `docs/INSTALL.md` again.

## Dashboard design

- **Theme.** Dark is the default; a dark, light and system switch sits in the
  top bar and is remembered per browser. JetBrains Mono is the UI font,
  Inter stays for long prose such as descriptions and prompts. Scrollbars,
  dialogs, menus, inputs and the YAML editor follow the same palette in both
  themes. The apb logo replaces the old wordmark.
- **Colors carry meaning.** Each profile gets a stable color used by its node
  cards, legends and chips; judge nodes are green, human gates amber. Run
  states use blue for running, green for done, red for failure and amber for
  paused or waiting, always next to a text label or glyph.
- **Playbook page.** The playbook, its status, effects and trigger sit in a
  left column, the graph in the middle, and the selected node on the right
  with its profile, agent, model, expected time, routes and prompt. Version
  history, stats, the fit report and known problems open in the right column
  too. Node cards show the profile and model, edges mark failure routes in
  red and fallbacks faintly, and a tall playbook opens at its top instead of
  shrunk to fit.
- **Run page.** A left rail lists the nodes in order with their state, the
  last note and the counters (attempts, tokens, cost, decisions, supervisor,
  worktree) next to the pause controls. The graph shows the walked path, the
  edge into the running node and a progress bar on it. On the right, the
  decision layer shows each decision with its confidence, then the current
  attempt, reviews, questions, host tasks and the outcome. The run log at the
  bottom streams the events, the journal and the supervisor report.
- **Lists.** Playbooks show their node count, profiles, the last runs, the
  success rate and the median run time; runs, profiles, connectors, approvals
  and the trash use the same rows and status bars.
- **Fewer requests.** The playbook list no longer fetches every playbook's
  detail: the playbook summary now carries `node_count` and `profiles`. The
  run history on the playbook list refreshes at most every ten seconds and,
  after the first load, only while the tab is visible.

## Fixes

- The run list is newest first across all projects. Before, the listing
  returned each project's runs as one block, so with "All projects" a newer
  run of one project could sit below every run of another.
- The duration column of the run list shows how long a finished run took.
  The run listing (`GET /api/runs`, MCP `runs_list`) now carries
  `duration_ms`: the active time from the start to the end of the run,
  paused time left out, the same duration `apb stats` counts. It is absent
  for a run that has not ended, including a finished run that was resumed
  and is live again.
- The playbook list loads its run history even when it is opened in a
  background tab, instead of showing empty run columns until the tab is
  shown.
- A run or playbook page whose playbook had two nodes ordering the same
  successors in opposite orders failed to draw its graph ("Not possible to
  find intersection inside of the rectangle"). Contradicting order hints are
  now dropped, and a layout that still fails falls back to a simple grid
  instead of failing the page.
- The run page no longer crashes on the model list when a node was re-run.
- A run page that cannot load shows the error and a Retry button instead of
  loading forever.

## Compatibility

No new journal events and no schema or CLI changes. API changes, all
additive:

- A run listing entry (`GET /api/runs`, MCP `runs_list`) has an optional
  `duration_ms`, and an optional `paused_ms` for a run that has not ended
  and was paused, so the run list counts a live run's time without its
  pauses.
- `GET /api/runs` without `?workspace=` returns the runs of all projects in
  one newest-first order (by `started_ts`) instead of one block per project.
- A playbook summary (`GET /api/playbooks`, MCP `playbook_list`) always
  carries `node_count` and `profiles` (profile names only, scope dropped).
- The playbook detail (`GET /api/playbooks/{id}`) carries
  `effective_effects`: the effects the run policy counts (inferred from the
  nodes plus the playbook's and each node's own declaration). The playbook
  page shows these instead of the declared list alone.

Clients that do not know the new fields can ignore them.

# apb 0.24.5

A patch release that gets apb ready for a wider audience: `apb validate` now
catches a profile or script a run would not find, every release archive ships
the license notices of what is compiled into the binary, the YAML backend
moves off an unmaintained crate, and the README, install guide and reference
docs were reviewed end to end.

## `apb validate` checks what a run needs

A playbook whose profile resolved nowhere, or whose script file did not exist,
used to pass `apb validate` with "OK" and then fail at run start. Two new
findings close that gap:

- **V91**: a profile referenced by a node or by `defaults.profile` resolves in
  no scope (project, global), or exists but cannot be loaded. The message
  names the scopes searched and how to create the profile. It is an error
  when only the project can provide the profile (a project profile that
  cannot be loaded), and a warning when the global store was the last place
  looked (`scope: global`, or `auto` falling through to it): the global store
  is machine-local, so a playbook whose profile lives there still validates
  in CI or a fresh clone. A missing `scope: project` profile stays error V14
  and is not reported twice.
- **V92** (error): a `script`, `success_check` or goal-criterion script does
  not exist in the version's `scripts/` directory, sits outside `scripts/`,
  or is a symlink that is absolute or leaves `scripts/`, where a run would
  not find it.

`apb validate` and the MCP tool `playbook_validate` report each with its
severity (an error makes `apb validate` exit 1 and `valid` false; a warning
does neither). `apb doctor` reports a missing script as a failing line, a
profile only the global store could provide as a warning line, and counts
both findings in the playbook's summary line, which no longer says "valid"
next to them. The dashboard's playbook view shows both as warnings. Saving a
playbook is unchanged: the dashboard and MCP save the YAML first and add
scripts afterwards, so nothing that saved before is refused now.

## Third-party license notices in every archive

Release archives now include `THIRD-PARTY-NOTICES.txt`: the copyright notices
and license texts of every Rust crate compiled into `apb` for the shipped
targets and of every npm package and font the embedded dashboard bundles.
The file is generated from `Cargo.lock` and `web/bun.lock` by
`scripts/third-party-notices.sh`; CI and the release test gate fail when the
committed copy is stale.

## YAML backend

The workspace moves from `serde_yaml_ng` to `yaml_serde`, the maintained
fork published by the YAML organization. The old crate depended on
`unsafe-libyaml`, which RustSec now lists as unmaintained (RUSTSEC-2024-0449),
so `cargo deny` failed. Parsing, error messages and serialized output are
unchanged.

## Docs

- README: a requirements section (platforms, supported agents), one
  install recommendation, a Quick start that runs as written (profile,
  playbook location, lint script, run), the full command list, and an index
  of the docs.
- `docs/INSTALL.md`: supported platforms, the glibc and static musl Linux
  builds, requirements, the `apb-update` helper, and a note that the `apb`
  crate on crates.io is a different project.
- `docs/MCP.md`: a table of the `supervisor_*` tools with the capability each
  one needs.
- `docs/HOWTO-authoring.md`: `schema` defaults to 2.
- `llms.txt`: Homebrew, six crates, absolute links, the remaining docs.
- `CONTRIBUTING.md`: build and test commands, and how to regenerate the
  notices; `RELEASE-CHECKLIST.md` is now the per-release checklist.
- Internal working files left the published docs, and local machine paths
  were removed from the historical design plans.

## Dashboard

The browser tab icon is now the apb logo instead of the default Vite logo.
The logo (a run log: four colored event nodes on a spine) lives in
`docs/brand/` as SVG for light and dark backgrounds.

The README opens with a banner showing a real playbook shape, including its
failure paths; `docs/brand/` also holds the 1280x640 image used as the
repository's social preview and the HTML source of both.

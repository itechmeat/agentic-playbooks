# apb 0.15.0

This release lands the nine deferred followups from the 0.14.0 resilience and parallelism work: the concurrent batch now honors stops, progress reports name the node that produced them, implicit fan-ins may batch again, batch cache keys stop depending on the chunk cap, the drive loop journals every hop it takes, the validator gains two warnings, and a run whose driver died is visible from every listing.

## Run control

A stop now reaches the concurrent batch. An abort kills members in flight and stops admission of queued chunks; a pause defers the queued members instead of writing them off, so a resume still runs them. (#77)

Cancelled members journal one consistent shape on both paths: a member skipped at the chunk boundary and a member killed mid flight both record a start paired with a cancelled finish, and both resolve `{{nodes.<id>.output}}` to the same text. A killed script node's output now reads `cancelled` on the sequential and `join: any` paths as well, where it previously kept whatever partial stdout the process had produced. (#77)

Progress reports carry the node that produced them, so a report posted by a concurrent batch member is attributed to that member instead of whatever node the scheduler was looking at when it drained the queue. Reports without the field keep the old attribution. (#78)

## Scheduling and cache

An implicit fan-in, a node that waits for all of its inputs without declaring `join`, may now run as a batch member, so two consumers of the same producer pair no longer serialize. Only nodes with an explicit `join` stay on the sequential path, which is the class the exclusion was written for. (#79)

A batch member's cache key no longer depends on `max_parallel`: the pre-execution workspace fingerprint is taken once per logical batch, so changing the cap no longer invalidates cached entries past the first chunk. A store rejection caused by a sibling's write into the shared workspace is now journaled as `workspace shared with concurrent batch siblings`, distinct from a real workspace change. (#80)

The drive loop journals every hop it actually takes, so a resume rebuilds branch heads that a re-derivation from current state alone would forget, including a hop taken under a third node's earlier status. One residual is documented rather than fixed: hops journaled on earlier passes of a loop keep both branches of a fork inside that loop live, so an `all` join downstream of such a fork can wait on a branch the current pass will not take. (#82)

## Validation

Two new warnings, V39 and V40, extend the condition edge checks past condition nodes: an `output_field`, `output_match` or `node_status` edge hung off any node kind now gets the same source checks that edges off condition nodes always had. Both are warnings, so no existing playbook starts failing validation. (#83)

V38's remediation advice now names the two shapes that actually resolve a cross branch read, routing the read behind the source or behind a node that joins both branches. The previous advice suggested a `join: all` that is a no-op for the most common flagged shape. (#81)

## Visibility

A run whose driver process is provably gone is marked in `apb runs`, in the MCP `runs_list` and in the dashboard run list, so a driverless run reads as needing a resume instead of as still running. A pid that cannot be probed is never reported dead. (#85)

`AttemptStarted` now records how long the agent process spawn took, so a first exec stalled by the platform's binary scan is legible in the journal instead of looking like a hung agent. (#85)

## Agents and docs

agy, codex and opencode gain verified non-interactive permission arguments on autonomous nodes, so an authorized effectful run no longer blocks forever on a permission prompt nobody can answer. hermes ships no verified flag, and `apb doctor --run` now warns when an autonomous node binds an agent with no non-interactive permission mode. (#85)

docs/PROFILES.md documents each built-in agent's autonomy capability and the stdout-only reviewer profile pattern, and docs/INTERACTIVE-AGENTS.md distinguishes the two OpenCode headless resume failure modes. (#84, #85)

## Compatibility

Every new field is additive and defaults to the old behavior: no journal migration is needed, an old journal folds to the same routing decisions it did before, and an MCP client or dashboard that does not know the new fields is unaffected.

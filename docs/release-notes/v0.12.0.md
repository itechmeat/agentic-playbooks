## apb 0.12.0: an agent that remembers no

The offer-to-save flow shipped in earlier releases had a memory problem on both sides. The agent forgot its own suggestions: a "not now" evaporated with the session, and the next session asked again. And when the user did say never, the dismissal was a bare slug invented by the model, so the same action renamed a month later slipped straight past it. This release replaces that store with one that remembers what was offered, how firmly it was declined, and where.

A suggestion decision is now a record with a synopsis, one sentence describing the action that was offered. The catalog returns active records whole, and matching moved from slug equality to the model comparing the candidate action against each synopsis by meaning, which survives every renaming the model itself is prone to. Soft declines escalate on a backoff schedule, one day, then seven, then thirty, then ninety, so a suggestion the user keeps waving away asks less and less often without ever going silent for good on its own. A hard dismissal holds one long fixed window and renews when declined again; the wording across the tool description, the dashboard and the docs now says exactly that instead of promising a forever it never delivered. Records live in project or global scope with a stricter-wins merge, the schedule is overridable per key in the global and project config, and the old dismissed.json migrates on first contact from read and write paths alike.

The user finally has surfaces for all of this. `apb suggestions list` shows both scopes with kind, decline count, expiry and synopsis; `allow` removes a record and honestly reports when the other scope still silences the pattern; `reset` clears a soft record's backoff without losing its synopsis. The dashboard's playbooks page grew a silenced-suggestions section with the same honesty, global records collapse into a single all-projects row, and the API serves the machine-wide global store even when no project is registered. `apb doctor` validates the suggestions config section, and `suggestion_dismiss` reports config diagnostics instead of swallowing them.

Getting the offer to fire at all turned out to be a host-integration problem, and this release ships what controlled headless experiments proved works. Claude Code truncates MCP server instructions at 2KB and defers tool descriptions entirely, so the tier-0 text was rewritten imperative-first and trimmed under the cap, and `apb init` now offers a consent-gated standing block for the project's CLAUDE.md and AGENTS.md, written idempotently next to the feedback-loop section. With both in place the agent checks the catalog before acting, offers once after finishing a repeatable action, records a soft decline with an escalating snooze, and stays silent in later sessions on a semantic match, all verified end to end against a live coding agent.

The store earned some paranoia along the way. Mutations run read-fold-write under one directory lock and refuse to proceed when the lock cannot be taken instead of writing unlocked; a store file from a future schema version is read-only refused and never rewritten or downgraded; a corrupt store is quarantined aside instead of being replaced on the next write; a global write with no config directory to land in errors instead of confirming a save that never happened; patterns are validated with the shared slug rules at write time so nothing unremovable can be recorded; and pure reads never create `.apb` in a directory that never adopted apb, while a project-scope decision adopts the root on purpose and says so in the docs.

Every official connector now ships two documents. README.md is the human page, opening with a paste-ready prompt that hands the whole setup to an agent; INSTALL.md is the runbook that agent follows, from install and credentials through scoped account config, the secrets dotenv flow, trust approval and a live healthcheck, ending with the one thing only the user can do, inviting the bot in or subscribing it to a stream. The runbooks state the real HTTP contract of the healthcheck endpoint, name the arguments the manifests actually require, and `apb connector init` scaffolds both files so the convention holds for connectors that do not exist yet.

The repository's own development playbook moved to 1.12.0, closing both routing holes around task selection: a failed pick no longer coasts down a success path whose marker happened to appear in its output, and a successful pick whose output matches no branch now lands in the abort path instead of dying with a missing-edge complaint.

Gates green throughout: fmt, clippy with warnings denied in debug and release, the workspace test suite, code-ranker with no violations, the frontend check, 369 frontend tests and the production build.

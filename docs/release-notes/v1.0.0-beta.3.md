# apb 1.0.0-beta.3

The third beta of apb 1.0, and the largest step since the beta line started.
A run now keeps result snapshots of what its nodes produced and can prove
its claims against them; approvals and person-only gates decide who may
pass a gate; a new setup command wires apb into the agent hosts on a
machine; costs show on every surface and a billed-use policy can require a
confirmation before an expensive run. The schema, the journal and the CLI
grow with the features; older binaries keep reading the journal and refuse
only the runs that use a feature they do not know (see Compatibility).

## Installing the beta

1.0.0-beta.3 is published as a GitHub pre-release. The `latest` release, the
Homebrew formula and `apb self-update` stay on 0.25.0, so existing installs
are not moved to the beta.

Shell installer for this tag (macOS, Linux x86_64):

```sh
curl --proto '=https' --tlsv1.2 -LsSf https://github.com/itechmeat/agentic-playbooks/releases/download/v1.0.0-beta.3/apb-installer.sh | sh
```

From source (see `docs/INSTALL.md`, section 5; `cargo install --git` is not
supported because the web frontend must be built first):

```sh
git clone --branch v1.0.0-beta.3 https://github.com/itechmeat/agentic-playbooks && cd agentic-playbooks
(cd web && bun install && bun run build)
cargo install --path crates/apb-cli
```

The archives on the release page can also be downloaded and verified by hand
as described in `docs/INSTALL.md`, section 4. To go back to the stable line,
run the `latest` installer from `docs/INSTALL.md` again.

## What a run keeps

- **Result snapshots.** A node that declares `results:` keeps a snapshot of
  its work at every settlement: the output, the declared fields and, on
  success, the declared files, content addressed under the run and scrubbed
  of secrets. Every read re-verifies the stored bytes against their
  digests, and `apb results clean` removes only what no journal stamp names.
  `apb results`, MCP `run_results` and the run page show the same view.
- **Evidence for claims.** An `agent_task` can declare an `evidence:` block
  that opens a bounded reading session over the snapshots of other nodes.
  The attempt reads it with `apb evidence read`, and the claims it makes
  about the outputs are checked against what it cited: the run shows each
  claim as structurally valid or not supported, never as confirmed.
- **Execution identity.** Every attempt records the executor and model that
  served it, so the run surfaces credit cost and tokens per chain step and
  `apb stats` can report what each executor group did. A daily cleanup
  removes what no longer serves.
- **Proven routes.** Every edge has a stable address shared by the engine,
  the validator, the version diff and the editor. The run page draws each
  segment under its own journaled definition and shows every edge as taken,
  not taken or not established, from journal evidence only, with a
  "why it did not run" explanation for nodes the journal proves never ran.
- **Interventions and search.** `apb stats` counts how often people had to
  step in, by category, and a playbook can mark params as `search: true` so
  `apb runs --field`, MCP `runs_list` and `GET /api/runs` filter runs by
  their values.

## Approvals and gates

- A `human_review` gate can bind its approval to the exact snapshots it saw,
  and a node with `requires_approval` is re-checked when its execution
  begins. An approval is a fact about stored bytes, never a consent.
- A gate marked `person_only` takes a decision only at a terminal or in a
  dashboard session with keys; MCP and a run step are refused, and a run
  step never decides for its own run tree.
- A supervisor patch never weakens approval fields, and a resume that would
  move past a gate without its decision is refused.
- A finish the gates refuse parks under the supervisor instead of vanishing,
  and the run ends with the approval reason.

## Checks for people

- A judge node can be evaluated outside a run (`apb judge eval`), labelled
  examples of its answers can be collected and filled from a run, and the
  keyless demo playbook shows the whole loop without API keys (`apb demo`).
- A candidate's summary separates blocking items from things worth a look,
  and a person promoting a candidate names the summary they decided on.
- The review decider and the unattended panels round out what the run page
  shows while a gate waits.

## Cost and billing

- Every surface shows a cost basis for a run: per node, per executor and
  per attempt, from the models the attempts actually reported.
- A playbook can declare a billed use with a predicted basis; the launch
  gate refuses a start above the project's limit and can require a typed
  confirmation, rechecked by the drive before it writes the manifest.

## Setup and defaults

- `apb setup plan` and `apb setup apply` read a machine, register apb as an
  MCP server in every agent host that can hold one, install the
  end-of-turn save check as a Stop hook, and write role profiles with the
  bundled defaults; `apb setup remove` undoes it. A changed shipped default
  is replaced only on a person's request.
- The bundled playbooks and skills install into the global store as
  ordinary versions, and an upgrade reconciles the installed defaults.
- Notifications gain a machine and project settings file (`policy.yaml`)
  with filters by playbook and outcome, and host task and supervisor waits
  notify while they are open.

## Runs that wait, and runs alone

- A node with `retry_delay` waits before its next attempt without holding
  the machine: the run releases, one waker per wait resumes it when the
  retry is due, and surfaces show the wait. `--retry-now` and the dashboard
  button start it at once.
- A node can declare `read_only`, enforced in the sandbox or checked as a
  before and after comparison, and a run can be unattended: waits that need
  a person fail with `hitl_required` instead of blocking, and a review may
  declare an unattended decision the validator and the launch check bound
  to safe outcomes.
- A run can declare its `outputs:` block, projected from the journal on
  every surface, and a spent bounded edge ends in a named dead end.
- Scenario runs (`apb eval --level quick|smoke`) check a playbook against
  scripted agent answers and a fixed decision book before an expensive run.

## Secrets and launch policy

- Declared secret params are redacted on every surface that is not the
  executor, and removed from decision requests whatever the playbook says.
  `apb mcp --read-only` serves an allowlist of tools behind a process-wide
  guard.
- A playbook's `agent_launch: allow | ask | deny` decides what may start a
  run, with a nonce-carrying confirmation for `ask`, rechecked by the
  engine before the manifest is written. The floor rises automatically at
  each publication and lowers only through a person's confirmed editor or
  terminal action.

## Fixes

- `apb results` loads and verifies the view once for its text listing, and
  the run page fetches the results again only after a settlement or the end
  of the run, so an ordinary journal notice re-hashes nothing.
- The run redactor is resolved only once a snapshot is actually stamped.
- A gate's terminal command starts in the run's project directory.
- A judge sandbox question that gets no answer is reported as unanswered,
  not as a disagreement, and a late sandbox answer cannot leak into the
  next judge node's state.
- The decisions report names the rule, not the model, for a legacy
  threshold; a host group whose attempts had no hint shows no hint line.
- The journal reads an `exec.entered` of another shape as absent instead of
  failing the fold, and the daily cleanup finishes on a git that cannot
  list worktrees with `-z`.
- The Discover page indents a git worktree row once, and the new playbook
  and profile editors preselect the first project row shown instead of the
  first project as stored.
- Recorded confidences and score levels are rounded for display, a
  server refusal shows the server's own sentence, and "fill from a run"
  says what it copies, from where and into what.
- A refused final notification is retried after the run ends, a list item
  whose agent CLI cannot start never falls back to a host task, a broken
  pipe exits quietly, and a start without a needed param value is refused
  on every launch surface.

## Compatibility

The journal, schema and API changes are additive; clients that do not know
new fields can ignore them. New journal events are safe for older binaries
to read, and a run that relies on a new feature (deferred retries with the
wait open, evidence sessions, bound approvals, read-only or unattended
runs, a billed use) carries a run guard that makes an older binary refuse
to resume it; an older binary can still stop and list such a run, and a
run it stopped itself can be resumed past its gates. `apb doctor --run`
lists the binaries that drove a run and any drift it sees.

- New CLI commands and surfaces: `apb setup plan|apply|remove`, `apb demo`,
  `apb results show|clean`, `apb evidence read`, `apb version list|use|history`,
  `apb candidate`, `apb problems`, `apb notify`, `apb launch floor`,
  `apb runs --field`, `apb eval --level quick|smoke`, `apb wait --follow-auto`
  and `apb resume --retry-now`.
- New MCP tools follow the same surfaces (`run_results`, `run_evidence_read`,
  `setup_plan`, `setup_howto`, the judge sandbox and examples, scenario
  runs, `playbook_stats`); `apb mcp --read-only` serves a read-only
  allowlist of them.
- New HTTP routes: the results listing and download, evidence, the graph
  draft validation and run overlay, current-version moves with history,
  notifications, memory, estimate, fit, quality, scenarios and the demo.
- The web frontend regenerates `api.gen.ts` and `consts.gen.ts` from the
  server's TypeScript contract, so dashboard builds need a current
  apb-server; `bun run build` in `web/` remains part of installing from
  source.
- `retry_delay` on a node is validated by rules V126 to V130 and the run
  `outputs:` block by V131 to V135; approvals, read-only, unattended,
  evidence and the launch policy carry their own rule families, all refused
  by older validators as unknown schema fields.
- Dependency updates: mail-parser 1.0, rusqlite 0.41, jsonschema 0.60 and
  the usual web and Rust groups, happy-dom included for a security alert.

## apb 0.11.0: failure routing you can see

A playbook that draws a `node_status: failure` edge from every node into one negative finish node buries its own structure. In this repository's own development playbook, 14 of 34 edges entered a single `aborted` node and said nothing except "this went wrong". This release adds one declaration that lets them go, and then makes the canvas say out loud what the graph used to leave implicit.

`defaults.on_failure` takes three values. `route` is the default and is exactly today's behavior: a node that ends failed or timed out with no edge to take that failure is an engine error. `stop` ends the run as failed on purpose, with the failing node's own output as the reason rather than a complaint about a missing edge. A node id routes the failure to that node, precisely as an edge into it would have, which is what keeps a negative `finish` node that composes a written failure answer working while every edge into it is deleted. An explicit edge always wins, so the branches that actually handle something (a review that routes into a fix, a check that routes into a retry) stay as they are; only the edges that led nowhere but the end of the run disappear. Anything that is not `route` or `stop` is read as a node id, so a misspelled reserved word surfaces as the new validator code V35 instead of being silently ignored, and the reachability rule now counts the policy as a route so the handler does not read as unreachable the moment its last incoming edge is deleted. The policy governs autonomous runs: a supervised run parks a failed node for its supervisor and never consults routing at all. Both repository playbooks moved to it, taking `apb-task-implement` from 34 edges to 21 and `apb-task-brainstorm` from 7 to 4.

Several edges leaving one node used to leave from one point, which hid two opposite meanings: unconditional edges all run in parallel, conditional ones pick exactly one. It also hid that the pick is first-match, so declaration order decides the route. Each edge now leaves from its own named point along the bottom of the node, captioned with why it is taken (`success`, `failure`, a review decision, a matched marker, `else` for a fallback), and the node carries a mode badge: `1 of N` with the exits numbered in the order the engine checks them, or `all N` for a fan-out where numbering would be meaningless. The condition moved from the middle of the line to the exit it belongs to, so nothing is said twice; a single-exit node keeps its plain dot and its line label.

The node editor is no longer a 240px rail. Clicking a node opens a full-width form over the canvas, the way `diff` already worked, with short fields paired two to a row, the success check on one line with its mode, and prompts capped at 300px with a scrollbar so a long one cannot push the rest off screen. Every field carries a written label instead of its raw schema key, and an "i" beside each label explains what the field does in one or two sentences. The explanation opens on hover for a pointer and on tap for a finger, so it is not invisible on a phone. The same form opens read-only from the playbook view, where a prompt stays selectable and scrollable rather than greyed out.

The YAML source moved out of the permanent left pane and onto a button next to `diff`, taking the canvas on demand and giving it back when closed, with modern syntax highlighting (CodeMirror 6) that arrives only when a YAML overlay is first opened. The view page has the same button with the editor read-only. Escape closes whatever is on top, in the order it was opened, and it defers to a dialog, select or popover that should close first. Adding a node moved from a stack of buttons parked over the graph to a selector in the topbar, with `finish` last.

Version history is no longer a permanent side panel; it opens from a button and starts closed. Any stored version can now be made current, newer or older: the old condition offered the switch only for a supervisor patch that had not been promoted yet, and an ordinary version is created already promoted, so in practice there was no way back. `promote_version` no longer requires a provenance sidecar for that, and now requires what actually matters, a version directory holding a `playbook.yaml`, so `current` cannot be pointed at an empty one.

Three diagnostics improved. A failed run finally says why on the dashboard: the run detail carries the reason folded from the journal, which until now was reachable only through `apb doctor --run` or an MCP call. An agent that writes its diagnosis to stdout and then exits non-zero no longer loses it, since the failure message keeps both streams instead of stderr alone, which matters more now that this text can be a run's failure reason. And the "New playbook" page, which was rendering but responding to nothing at all, works again: its reload effect called a function whose synchronous prefix read and wrote the same piece of state, so the effect depended on a value it had just written and the page remounted in a loop, refetching the project list 89 times and counting.

The frontend is also split by route. Every page except the landing list is a dynamic import, so the entry chunk fell from 794 KB to 50 KB raw and the first screen from 225 KB to 76 KB gzipped, with the graph canvas, the YAML model and the connector screens arriving only when a route needs them. Each route carries all three await branches: a pending indicator that fades in only after 200ms, so a locally served chunk shows nothing rather than a flicker, and a recovery screen for a chunk that never arrives, which is what happens when the apb binary is replaced under an open tab.

Gates green throughout: fmt, clippy with warnings denied in debug and release, the full workspace test suite, `code-ranker` with no violations, the frontend check, 346 frontend tests and the production build.

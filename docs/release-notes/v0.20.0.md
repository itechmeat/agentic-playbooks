# apb 0.20.0

This release teaches apb to receive inbound HTTP. Three pieces land together: an authenticated server-deployment mode, a generic webhook-ingest subsystem, and the fourteenth official connector, whatsapp, which is the first one that both sends over REST and receives through the ingest listener. Alongside them comes a batch of engine, server and validator fixes from two production field reports.

## Server mode

apb can now run as an authenticated deployment behind a domain. `apb server key` issues, lists and revokes static API keys: a key is `apb_` plus 256 bits of randomness, only its SHA-256 is stored, and verification is a constant-time compare. A browser session is an HttpOnly cookie with a sliding TTL, bound to the key that minted it, so revoking a key ends its sessions. Cross-site writes are refused through a marker header, repeated credential failures are throttled per source address, and binding to a non-loopback address requires a key to exist first. Key files are re-read on change through a content hash, so rotating a key does not need a restart. The runbook is `docs/DEPLOYMENT.md`. (#104)

## Webhook ingest

A separate listener on its own socket receives provider deliveries, structurally isolated from the dashboard API router. A connector manifest can declare a `webhook` block: an HMAC-SHA256 signature scheme over the raw request bytes, a challenge handshake for providers that verify a callback URL, and the JSON path to the provider's own message id for deduplication. Verified deliveries land in a machine-scoped append-only inbox with a time-based dedupe window, and playbooks read them through a new `inbox` function kind: `inbox_read` in a node, process, `inbox_ack`. Two validator rules cover the new surface, and connector contract tests can exercise inbox functions offline. (#104)

The important consequence for integrations: an inbound delivery no longer needs a run to be startable at that instant. Deliveries are stored whether or not the workdir is busy, and a node polls them when the run reaches it. (#104)

## The whatsapp connector

Sixteen functions against Meta's WhatsApp Cloud API (Graph v23.0): text, template, media and read-receipt sends, template management on the WABA, business profile and phone number reads, media URL and delete, plus the three inbox functions. The send half works from any apb install with a System User token; the receive half needs the server-mode plus ingest deployment, because Meta has no polling endpoint for inbound messages and delivers them only as webhook POSTs. `connectors/whatsapp/INSTALL.md` walks the Meta app setup end to end, including registering the callback URL, and a demo playbook shows the send plus poll-and-ack loop. Eighteen offline contract cases ship with it; a live smoke against a real WABA number is a later confirmation pass. (#104)

Two limits are documented rather than worked around: outside the 24-hour customer-service window a plain text send fails and a template is required, and media is sent by hosted link or by a media id obtained out of band, because the connector schema expresses JSON bodies and form fields but not multipart uploads. (#104)

## Delegation to connector-binding children now works from the dashboard and the CLI

A parent playbook that delegates to a `type: playbook` child which binds a connector could previously only be started through MCP. The HTTP and CLI start paths walked only the top-level nodes when computing connector permits, so the child run received empty permit maps and died at the fail-closed check. Both paths now run the same recursive child walk the MCP gate already used, through one shared seam so the verified map is never recomputed between the gate and the run. Bridge-started playbooks no longer have to be leaves. (#105)

As a side effect children now also pass lifecycle, `requires` and cycle checks and receive the digest and profile-bundle pins they never had on those two paths. A parent whose child is draft, retired, unresolvable, cyclic, or bound to an untrusted connector or account now refuses at start instead of failing mid-run. (#105)

## Engine fixes

A terminal supervisor command queued behind a command that cannot be consumed yet is no longer starved. Previously an operator's pause in that position was silently ignored and the run kept executing nodes; now the first `Abort` or `Pause` anywhere in the pending queue is consumed and the superseded retry is journaled. (#105)

Every cancellation write-off journals the same shape: a paired start plus a cancelled finish carrying `cancelled` as its output. Three separate sites used to emit an unpaired finish with an empty output, so a consumer that pairs starts with finishes, or a template reading a cancelled node's output, saw two different shapes depending on why the cancellation happened. (#105)

A run parked on a wait with a live driver reports `Running` instead of `Interrupted`, and the run-detail endpoint now carries the same liveness overlay the run listing already had, including `driver_alive` and repaired node statuses. A driverless run reads as needing a resume on the detail view, not just in the list. (#105)

A connector call budget is no longer spent by a previous failed attempt. `max_calls` now counts from the current attempt, so a fallback executor starts with the budget the playbook granted rather than whatever a dead attempt left behind, and the refusal message says which attempt spent it. The trade-off is stated in the docs: the worst case per visit is now attempts times `max_calls`, where attempts counts retries, every fallback step and the infrastructure-retry backoff steps, and where an interactive node in reprompt or resume mode starts a fresh count per round. Size inbox-reading grants accordingly. (#105)

## Server and API fixes

Posting a review decision for a node that is not a review gate of the run answers 404, and posting when nothing is pending, or when a decision is already queued and unconsumed, answers 409. Previously any node name was accepted with a 200 and the decision went nowhere, or a duplicate was silently applied at a cyclic gate's next visit. MCP and the CLI inherit the same contract. (#105)

`GET /api/runs?workspace=<id>` filters the listing to one workspace; the no-parameter aggregate is unchanged. A second concurrent start against a busy workdir answers 429 with `Retry-After` instead of 500. The run-detail read tolerates a torn trailing line in a concurrently-appended event log rather than failing the whole request while a run is executing. (#105)

## Authoring

Templates support a top-level field selector: `{{nodes.<id>.output.<field>}}` projects one field out of a node's JSON output, with the same semantics the `output_field` edge condition already had, so anything the projection cannot read renders empty rather than erroring. Downstream prompts no longer have to interpolate a whole JSON blob and explain which field to read. (#105)

A `human_review` node takes an optional `prompt`, shown at the gate on every surface including the dashboard review panel. It used to be accepted and silently dropped. (#105)

`apb import` honors the version inside a bundle when that version is free, errors naming the conflict when it is taken, and auto-assigns as before when the bundle carries none. Re-installing a corrected 1.0.0 no longer requires deleting the installed directory. (#105)

V39 and V40 stop warning about routing that `defaults.on_failure` already covers, while a node missing a success route still warns and the V09 error stays strict. The atrip connector's post-booking ancillary functions now carry the vendor order identifiers they were silently dropping, so a post-ticketing baggage transaction can identify its order. (#105)

## Documentation

`{{run.hooks.*}}` is documented as what it is, the relative signal URL for a wait node's hook, not the payload posted to it, and the two things now called hooks are disambiguated: the run-signal endpoint discards its body, the connector-ingest endpoint stores it in the inbox. A `goal` block is stated plainly as a declarative contract with no runtime enforcement, and `run_report` now surfaces it verbatim and labeled as unevaluated so a supervisor can check it by hand. The trust posture of CLI and dashboard starts is written down: connector and account trust is enforced at every depth on every path, while playbook and profile-bundle trust for children follows the same posture as the parent. (#105)

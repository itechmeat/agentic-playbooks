# apb 0.22.0

A minor release that covers seven feature pull requests. It adds optional decision models (small typed models that answer a judgment in a fraction of a second), records the tokens every agent attempt spends, lets this and later binaries read journals written by a newer apb, gives a run a working tree of its own, lets a node continue another node's agent session, and folds in a round of token economy, consolidation and hardening work. The playbook schema stays at 2: every new playbook field is optional, and playbooks written for 0.21.0 keep working, with the behaviour changes listed under "Upgrading".

## Decision models, off by default

Some judgments inside a run are small: whether a successful agent reply is really a finished result, which branch a playbook takes, whether a retry is worth it, what a supervisor or reviewer is likely to do, which executor tier a step needs, which saved playbook fits a task. Until now each of them needed an agent turn or a person. Decision models answer typed questions (`choice`, `score`, `noul`) over a text state with probabilities, and apb can now ask them. (#170)

The layer is optional and off by default. Without a `<config_dir>/decisions.yaml`, apb behaves exactly as before: no request, no event, and manifests, journals, CLI output and MCP responses are unchanged. The file is a sibling of `config.yaml` with its own `version`, so older binaries never read it. The `systemone` provider kind covers TypeSafe, OpenRouter, Vercel, OpenCode Zen and self-hosted servers; new kinds `vercel_evaluate`, `openrouter_decisions` (alpha) and `cloudflare` cover other APIs, and `llm_emulation` (uncalibrated) asks an OpenAI-compatible endpoint or a node's own profile. Keys are references only (`{{env.VAR}}`, `{{cmd:...}}`), with a per-run budget, redaction and a `privacy.send` list of what may leave the machine. A project's `.apb/config.yaml` may only narrow what the machine allows: lower modes, drop material classes, keep requests on local providers. It can never add a provider, a URL or a key. `apb doctor` gets a decisions line with provider ids and kinds and reachability, never a key, and flags model aliases, since thresholds do not transfer between model versions. (#170)

Every use starts in shadow, which journals the answer and acts on nothing. Advise shows the answer where a person or a supervisor decides. Enforce acts only with a threshold stored for the exact use, provider and model, under a per-use action cap (3 by default) and, for uncalibrated providers, an explicit `allow_uncalibrated`. Facts stay in code: trust, gates, preflight, validation, liveness, counts and exit codes are never delegated, and the decision layer never fails a node or a run by itself. (#170)

The uses in this release:

- A completion check on successful agent attempts. In shadow it journals; in advise it raises an anomaly wake; a node can opt in to `completion_check: enforce`, which needs a stored threshold and a retry left.
- A new `judge` node type and a `judge` edge condition. `on_unavailable` (`route`, `default`, `fail`, `emulate`) decides what happens when no model answers, so a playbook with judges runs on any machine. Answers route only at enforce.
- Retry advice, supervisor wake pre-triage (`wake.triage`), a review gate recommendation (`review_requested.recommendation`, also in MCP `pending_review`) and executor tier routing (profile `tiers`, node `route: auto`). The review auto-decision can only choose `needs_changes`, fails closed, and is refused on playbooks that declare `irreversible` or `secrets` effects, run merge, push, deploy or publish steps after the gate (V72, V73), inherit such effects from a sub-playbook at any depth, or run as a sub-playbook themselves.
- An opt-in `playbook_catalog(query)` ranking over MCP. It is advisory: entries are never filtered or reordered, and each ranked item repeats the entry's `trusted`, `lifecycle` and `ambiguous` facts.

Every answer is a `decision_made` event in the run's journal. Resume replays journaled decisions without a new request, and a replayed action repeats only while the use is still in enforce and the rest of the enforce gate still holds. A run's snapshot of the settings can only narrow what the machine's `decisions.yaml` allows at that moment. Totals appear in `apb runs` and `apb wait`, in MCP `run_status` and `run_report` (`decisions`), and on the dashboard as a Decisions card and event notes. `apb decisions report` measures a use against what actually happened, `apb decisions thresholds set|list` stores the thresholds enforce needs, and `apb decisions replay` asks another provider the same questions. So far only the completion check has a labeller in the report; the other uses say so. (#170)

`APB_DECISIONS=off`, an `off` mode, a lowered ceiling or a project opt-out stops every decision-provider call, re-checked before each decision so it applies mid-run. The provider layer bounds `retry-after` and the parsing of emulated replies, and validates reply model names, costs and error reasons before they reach the journal. The dashboard gains a judge node editor, judge edge captions, the review recommendation, the wake triage note and read-only profile tiers. Validator codes V50 to V61 and V70 to V74 cover the new fields. The reference is `docs/DECISIONS.md`. (#170)

The repository's own `apb-task-implement` 1.15.0 still routes a well-formed `needs_brainstorm` marker in code and asks a judge only about a task without one; without a provider it behaves as 1.14.0. A new example, `examples/playbooks/review-triage.yaml`, shows a review gate with a judge. (#170)

## Agent output as JSON, and the tokens an attempt spends

The built-in claude, codex and opencode forms now ask the CLI for its JSON output (claude `-p --output-format json`, codex `exec --json`, opencode `run --format json`; zcode already used `--json`), and so do the resume forms. apb unwraps the reply from it and journals the attempt's token usage on `attempt_finished`: input, output, cache read and cache write tokens, a cost when the CLI printed a non-zero one, and `source: reported`. Nothing is estimated by apb and there is no price table. The numbers are recorded as each CLI reports them, so they are not always comparable across agents; `docs/MCP.md` lists the differences. A failed attempt keeps its usage. (#168)

Run totals appear on every run view: `apb runs <run>` (a new optional argument that prints the run's nodes and a usage line), MCP `run_status` and `run_report` (`usage`), and a token line and per-attempt notes on the dashboard run page. (#168)

Reading the JSON result has side effects worth knowing. Headless claude, codex and opencode attempts now yield session ids, so `continue_session` resumes warm and interactive answer rounds resume the session instead of reprompting; prompts of existing playbooks that use either change accordingly. A custom `command` form for these agents that already asked for JSON now receives the unwrapped reply as the node output instead of the raw JSON. claude's `is_error` now fails the attempt in headless mode, as it already did on the `acp` transport. Custom forms without JSON, stub agents and plain-text agents behave as before. (#168)

## Journals an older apb can still read

From this release on, an event type a binary does not know is skipped and counted instead of failing the read. Read-only surfaces show "N unknown events (newer apb?)": `apb runs`, `apb runs <run>`, MCP `runs_list`, `run_status` and `run_report`, and the dashboard. The engine continues a run only when a checkpoint (`node_finished`, `run_paused`, `run_finished`, `run_aborted`) follows every unknown event; otherwise resume refuses before writing anything and names the binary's version. Stop is the exception: it only appends `run_aborted`, so an older binary can always stop a run a newer one started. Every future event type must be safe to skip up to the next checkpoint. (#168)

This protects binaries from 0.22.0 onward. 0.21.0 and earlier have no such rule, and journals written by this release carry event types they do not know, so a run started by 0.22.0 should not be resumed or inspected by an older apb.

## A working tree per run

A run can have a working tree of its own: passed at start (`apb run --worktree <dir>`, MCP `playbook_run` `worktree`, the dashboard API's `worktree` field), or declared by the playbook with a top-level `worktree:` template that resolves at start from `params` or when a named node succeeds. Every `agent_task` and `script` without its own `workdir` runs in it, a relative node `workdir` resolves against it, and sub-playbook runs inherit it. It is journaled once as `worktree_resolved` and shown by `run_status`, `GET /api/runs/<id>` and the run page. A tree that is neither a directory of the project nor a git worktree of its repository refuses the start or fails the run; it never falls back to the execution root. (#166)

The busy lock now covers the checkout a run works in. The execution root and its plain directories keep `.apb/workdir.lock`; a separate git worktree gets `.apb/locks/tree-<digest>.lock`. Runs over different worktrees no longer wait on each other, while overlapping trees still do. Run directories are created exclusively, so two starts of one playbook in the same millisecond no longer share a directory. (#166)

`cache: { mode: auto, key: "{{...}}" }` states what a node's result depends on: the rendered key replaces the workspace fingerprint in the cache key, and an empty key skips the cache. Admission is unchanged, so a key never hides a side effect. V48 and V49 validate what `worktree` and `cache.key` may read. (#166)

## Warm session handoff, named outputs and transcripts

`continue_session: <node>` makes a node's first attempt resume another node's agent session instead of a cold spawn, when the journal has a session id and agent, model and working directory match; otherwise it starts cold, and a `session_handoff` event says why. It works for claude, codex, opencode and zcode. `outputs.fields` makes the prompt name the exact status-file keys, and a missing one journals `output_fields_missing`. `workdir` on `agent_task` (parsed but unused before) and on `script` is now a template, and an empty render or a missing directory fails the node instead of running in the execution root. (#147)

Every attempt streams `attempts/<node>-<n>/stdout.log` and `stderr.log` into the run directory, so a killed or timed-out attempt keeps its output; for claude the session transcript is copied there too. Because those transcripts can hold account details, apb now keeps `.apb/.gitignore` covering every machine-local path it writes (`workspace.local`, `runs/`, `cache/`, `trash/`, `backup-*/`, `workdir.lock`, `locks/`, `decisions.jsonl`): missing lines are appended, existing ones are kept, before the first transcript is written. (#147, #148, #166, #170)

Saving an unchanged definition no longer creates a version: MCP, HTTP and `apb import` answer `unchanged: true`, also for a frozen playbook instead of the frozen error. The skills copy is one directory per profile per run, so the system part of an invocation is byte-identical across a profile's nodes and prompt caches can hit. V44 to V47 cover the new fields. (#147)

## Token economy

Retries and fallbacks on the same agent and model resume the failed attempt's session instead of starting over, and a timed-out attempt is continued, not re-run. Recorded output passed into prompts is bounded, with the full text kept in the run directory, and an interactive answer round sends only the answer. Profiles take `environment: minimal | full`, and minimal is now the default: a claude node runs without the operator's user-scope plugins and hooks unless its profile says `full`. The old `hermetic` key is deprecated: `profile.yaml` still accepts it but it selects nothing, and on the write surfaces (`--hermetic`, the MCP and HTTP field) `true` means `minimal` and `false` means `full`. Long waits happen on the server: the `run_wait` MCP tool, `apb run --detach` and `apb wait`. (#142)

## One source of truth

The CLI, MCP, validation and the dashboard share one agent and model catalog, one run view for every read-only run surface, one preflight gate and one launch path. Dashboard run types are generated from Rust and checked by a contract test. The server has an HTTP cache policy, real 404s for unknown API and asset paths, and a build id in `/api/health` and the `x-apb-build` header, so an open tab notices a newer server. `validate`, `doctor` and `adopt` check profile models, requirements and connectors against an optional `model_policy`. (#142)

## ZCode as an agent

ZCode is a built-in agent: detection, a login check in `apb doctor`, invocation with `--json` unwrapping, `zcode_mode: edit`, and the models `GLM-5.3` and `GLM-5.3-Flash`. An omitted effort now means `low` rather than `max`; in a measured review task `low` found the same planted defect in a fraction of the time and tokens. A model without `low` falls back to its highest level, and `@high` or `@max` in a profile still override it. Model ids are matched case-insensitively and written back in ZCode's own spelling. The Claude and Codex model lists are updated. (#142, #146)

`agents: { zcode: { ui_sync: true } }` in the global config makes headless zcode sessions appear in the ZCode desktop history. It only inserts into an existing history database, never creates one or changes its schema, and any failure is a warning that never fails the run. (#146)

## Trash and trust management

Deleted playbooks can be listed and restored: `apb trash list|restore`, MCP `playbook_trash_list` and `playbook_trash_restore`, and a dashboard Trash view that handles an id that exists again. Granted trust can be listed and revoked: `apb trust list|revoke`, MCP `trust_list` and `trust_revoke`, a dashboard Approvals view, and revoke on connectors. (#142)

## Hardening

Release artifacts now carry keyless build-provenance attestations (`gh attestation verify <file> --repo itechmeat/agentic-playbooks`, see `docs/INSTALL.md`), every action in the release workflow is pinned to a commit SHA, and publishing requires a test gate job to succeed. The dashboard sends a Content-Security-Policy without `unsafe-inline` or `unsafe-eval`. A dashboard without an API key answers only its own host names (add a proxy or public host name to `server.allowed_hosts`) and refuses browser writes to the API that do not come from its own pages. Supervisor tokens come from the OS random generator and are compared in constant time. Prompts are always passed after `--`, or guarded for `-p`-style CLIs. A project `skills_dir` must stay inside the repository, and a playbook's trust now covers its `scripts/` directory as well as `playbook.yaml`. (#142)

## Also fixed

- A failure carried past every route no longer finishes the run as success. (#142, #106)
- A supervisor directive that moves a run off a waiting review gate closes the open review request, journaled as the new `review_withdrawn` event, so the gate no longer reads as pending. (#142)
- A run reads as running while its driver finishes an exited attempt, journaled as the new `attempt_exited` event. (#142, #107)
- Wall-clock test flakes are replaced by readiness-based waits, tests no longer touch the real config directory, and orphaned drivers and temporary-file leaks are fixed. (#142, #108)
- Defects found while adapting playbooks for a second machine. (#142, #137)
- Dependency updates for the Rust workspace, the web app (including vitest 5) and the GitHub Actions. (#125, #126, #127, #129, #131, #134, #143, #144)

## Upgrading

- **Journals.** Runs written by 0.22.0 contain event types that 0.21.0 and earlier cannot read (`attempt_exited`, `review_withdrawn`, `session_handoff`, `output_fields_missing`, `worktree_resolved`, `decision_made`). Upgrade every apb that reads a project's runs, the dashboard service included, before starting runs with 0.22.0. From 0.22.0 on, a binary skips event types it does not know: it can read and stop runs written by a newer one, and resume them when a checkpoint follows every unknown event. New fields on existing events are optional and absent when unused.
- **Behaviour change.** A playbook that relied on "failed node, then an unconditional edge, then success" now ends failed. (#106)
- **Agent invocation.** The built-in claude, codex and opencode forms ask for JSON output, and headless claude attempts whose result has `is_error` now fail. A custom `command` form that already asked for JSON receives the unwrapped reply.
- **Saves.** Saving an unchanged definition creates no version; HTTP create answers `200` with `unchanged: true` instead of `201`. `workdir` on `agent_task` now takes effect.
- **Agent environment.** Profiles without `environment` now run minimal: claude nodes no longer load the operator's user-scope plugins and hooks. Set `environment: full` on a profile that needs them; `hermetic: false` in an existing `profile.yaml` no longer selects the full environment. Runs started before the upgrade keep the environment they began with. (#142)
- **Dashboard behind a reverse proxy.** For a dashboard without an API key, add its public host name to `server.allowed_hosts` (or set `server.public_base_url`), otherwise requests through the proxy are refused with `403`. Upgrade the binary before adding the key: an older apb refuses a config file with keys it does not know.
- **Strict files.** `config.yaml`, profiles and `decisions.yaml` refuse unknown keys. A profile with `tiers` or `environment` is refused by an older apb, a `config.yaml` with `server.allowed_hosts`, `model_policy` or `agents.zcode.ui_sync` likewise, and a `decisions.yaml` with the provider kinds new in this release is refused by a build without them (releases before 0.22.0 do not read `decisions.yaml` at all). Playbooks with `judge` nodes or edges, `continue_session`, `worktree`, `cache.key` or `outputs.fields` need this version.
- **Trust.** A playbook with a `scripts/` directory, and a profile whose content changed, needs one re-approval on its first run. The repository's own `apb-task-implement` 1.15.0 is a new version, so its trust has to be granted again before it runs.
- **Decision models stay off** until a `<config_dir>/decisions.yaml` exists, and every use starts in shadow. `APB_DECISIONS=off` switches the layer off for a process at any time, mid-run included.
- **`.apb/.gitignore`** gains entries for machine-local paths on the first run or `apb init`; commit the change.

# apb 1.0.0-beta.7

The seventh beta of apb 1.0 makes routines safe to leave to a scheduler
and widens what they can reach: a run starts once per event, ends at its
deadline, keeps one run per key and is judged across runs by health
rules; old runs are pruned into a signed archive; DeepSeek Harness joins
the built-in agents with NEAR AI Cloud models behind it; and official
connectors reach Gmail, Google Calendar, Google Drive and web search
through OAuth refresh and bounded paging.

## Installing the beta

1.0.0-beta.7 is published as a GitHub pre-release. The `latest` release and
the Homebrew formula stay on 0.25.0, and `apb self-update` of a stable
install stays on the stable line. A beta install from beta.4 on reaches this
one with `apb self-update`; an earlier beta uses the installer below.

Shell installer for this tag (macOS, Linux x86_64):

```sh
curl --proto '=https' --tlsv1.2 -LsSf https://github.com/itechmeat/agentic-playbooks/releases/download/v1.0.0-beta.7/apb-installer.sh | sh
```

## Routines a scheduler can start

1. Start keys. `apb run --start-key <key>` (MCP `playbook_run` and the HTTP
   start body `start_key`) makes a start happen once per event: a repeat
   with the same key and the same arguments starts nothing, prints `run
   already started: <run_id> (start key)` and, without `--detach`, waits
   for that run and exits like `apb wait` (MCP answers `already_started:
   true`). Another request under the key is refused `start_key_conflict`,
   a key that looks like a credential `start_key_invalid`, and a start
   racing a preparing one `start_key_busy`. A key whose run failed or was
   aborted is used again only with `--start-key-reuse`, a person's
   decision. Keys are kept 7 days (`runs.start_key_days` in
   `policy.yaml`), stored only as a MAC in a signed file under
   `.apb/start-keys/`; a file that does not verify refuses keyed starts
   `start_key_state_unreadable`. Details in `docs/CI.md`.
2. Run deadline. `deadline: 45m` in a playbook, `apb run --deadline 45m`,
   MCP and HTTP `deadline` end a run aborted `deadline_exceeded` once it
   has run that long, the time a person paused it left out, in every
   state: while it drives (attempts in flight get the graceful stop of a
   `--now` pause, an open host task is closed `cancelled`), queued for the
   working tree, paused or released (one deadline waker per run), and
   after a reboot (`apb resume --all`). A plain resume past the deadline
   is refused `deadline_passed`; `apb resume <run> --deadline 30m` (MCP
   `run_resume`, the HTTP resume body) grants more time. A value that does
   not parse is refused `deadline_invalid`, and a supervisor patch may not
   change the field (`deadline_changed`). Every run surface shows the
   deadline. Validator code V200.
3. Runs started from a run step. A start a step makes (`apb run`, MCP
   `playbook_run`, `playbook_trial`, `playbook_execute_plan`) records its
   verified starter as `started_by`; `apb runs <new>` prints `started by
   run <id> (node <n>, attempt <k>)` and the starter lists the runs its
   steps started in its project. Chains are bounded at five runs across
   projects (`start_chain_too_deep`), and a step of an external data run
   starts runs with the flag too.
4. Concurrency key. `concurrency: { key, on_busy }` keeps at most one
   active and one waiting run of a playbook per rendered key. `on_busy:
   queue_latest` (the default) lets the newest start wait and replaces a
   waiting one, which ends aborted `superseded:`; `supersede` also stops
   the active run gracefully; `refuse` refuses `concurrency_busy`. A run
   step never waits for or replaces its own run (`concurrency_own_run`),
   and a key that reads a credential-shaped value is refused
   `concurrency_key_sensitive`. A queued routine resolves
   `run.previous_success` once it holds the key. The slot state is a
   signed file under `.apb/concurrency/` (`concurrency_state_unreadable`
   when it does not verify). Validator codes V210, V211.

## Routine health and retention

1. Health rules. A `health:` block judges a watched playbook across its
   runs: `consecutive_failures`, `failure_rate: { at_least, window,
   min_runs }`, `overdue`, with `on_trip: notify` (the default) or `hold`
   and a `cooldown`. Rules are evaluated after every run end, by `apb
   health check`, by `apb resume --all` and by the dashboard every 10
   minutes, so an overdue routine trips even when nothing runs. A trip and
   a recovery each send one notice through the new `health` notify
   transition, which is in the default set. `on_trip: hold` refuses every
   start `playbook_on_hold` until a person runs `apb health clear <id>`;
   `apb health check` exits 3 while a playbook is on hold, so a scheduler
   can stop there. `apb health` lists the state, `mute <id> --until` and
   `unmute <id>` silence notices, `policy.yaml` `health.playbooks` names
   the playbooks a machine watches, and the state is a signed file under
   `.apb/health/`. `apb doctor`, `apb stats`, MCP `playbook_catalog` and
   `playbook_stats` carry it, and the dashboard's playbook list shows `on
   hold` and `tripped` badges. Validator code V212.
2. Pruning runs. `apb runs prune` removes old runs the retention settings
   of `policy.yaml` no longer keep (`runs.keep_days`, default 30;
   `runs.keep_last`, default 20; `runs.keep_failed_days`, default 90; a
   project file only lengthens them). Without `--yes` it prints the plan;
   `--json` and `--playbook <id>` narrow it. It never removes a live run,
   the newest, the latest success, a run with a pending follow-up, a
   graded or candidate trial run, an unknown send, a run a start key or a
   concurrency slot names, or a parent of a run it keeps, and it removes
   a run with all its descendants or not at all. Each removed family
   leaves a signed summary under `.apb/runs-archive/`, which `apb stats`
   and the health rules count, so a prune never makes a routine look new.
   A second prune in the same project is refused `prune_in_progress`;
   inside a run step `--yes` is refused, and no MCP tool or HTTP route
   prunes. Details in `docs/STATS.md` ("Pruning runs").

## Agents and models

1. DeepSeek Harness (`dsh`) is a built-in agent, verified against dsh
   0.2.2-rc.1: launched headless with its `--json` event stream (reply,
   session, token usage, tool calls, classified errors), resumed by
   session id, detected, checked by `apb doctor`, and registered by `apb
   setup` as an MCP host in its home patch layer. Models are
   `[<route>/]<model>[@<effort>]`: a bare `deepseek-flash` or
   `deepseek-v4-pro` runs on the official DeepSeek route, any other route
   is one you configured for dsh. dsh has no model flag, so apb passes the
   model as a run-scoped `--patch` file. Not supported on dsh: the live
   ask transport, the tool exposure check, an end-of-turn hook,
   `environment: minimal` and a sandbox (`isolation: full` refuses it).
   Details in `docs/AGENT-SETUP.md` and `docs/PROFILES.md`.
2. NEAR AI Cloud models. apb ships the public NEAR AI Cloud catalog in the
   binary and refreshes it only through `apb models --refresh`, `POST
   /api/models/refresh` and the dashboard's daily refresh (no credential
   sent; `cloud_models.near_ai_cloud.auto_refresh: false` in `config.yaml`
   turns the last off). `apb models` prints the rows. A dsh profile names
   `nearai/<catalog id>[@<effort>]` and runs with only `NEARAI_API_KEY`
   set: the run snapshots the catalog row, writes the provider route into
   dsh's run-scoped patch, replaces the key's value in everything it
   stores (`[redacted:NEARAI_API_KEY]`) and prices each attempt from the
   row (`priced_from`, basis `billed`). Every authoring surface checks the
   model (`cloud_model_unknown`, `cloud_model_no_tools`,
   `cloud_model_not_chat`, `cloud_effort_unsupported`), and a start in cli
   mode is refused on those and on a missing key (`cloud_key_missing`).
   Every row carries a privacy class (`confidential_tee`,
   `third_party_tee`, `incognito`, `unverified`); a chain that spans
   classes gets the warning `profile_privacy_class_changes`, and an
   attempt that left its executor's class is shown as
   `privacy_class_left`. A `decisions.yaml` `llm_emulation` provider may
   name `catalog: near-ai-cloud`. Validator codes V220 to V222. Details in
   `docs/CLOUD-MODELS.md`.
3. External data runs. A start with `external_data: true` (`apb run
   --external-data`, `apb eval`, MCP and HTTP `external_data`, the Run
   dialog's "External data" box) marks a run whose input comes from
   outside the operator. It is fixed for the run's lifetime, inherited by
   children and successors, and shown on every surface. Such a run keeps
   nothing for learning: no remembered input (`--remember` is refused
   `external_data_remember_refused`), no node cache write, known problem,
   correction, candidate trial, eval result, judge example or scenario
   capture, and every reader of earlier runs skips it. A resume asking for
   another value is refused `external_data_immutable`, and a learning tool
   pointed at such a run `external_data_run`. Details in
   `docs/EXTERNAL-DATA.md`.

## Connectors

1. OAuth refresh. The connector auth kind `oauth2_refresh` mints an access
   token from a refresh token at call time, keeps it in process memory
   only, refreshes it before expiry and once after a 401 (still one call,
   one event and one `max_calls` unit). Functions declare the `scopes`
   they need, and a missing scope fails before the request with the
   command to consent again. `apb connector oauth <connector> [--account
   <a>] [--scope <s>]` runs the loopback consent with PKCE at a person's
   terminal and prints the refresh token once; it is refused inside a run
   step and without a terminal. IMAP gains `auth_method: oauth2`.
2. Bounded paging. A read-only list function may declare `paginate:` (a
   body token or the `Link` header, `max_pages` default 5 and at most 20,
   4 MiB across pages); the items are concatenated and the result carries
   `pages` and `more`. A failed page fails the whole call.
3. New official connectors: `gmail` (search and read messages and
   threads, drafts in a thread, send a draft, labels, archive),
   `google-calendar` (list, read, create, update and delete events, with a
   new event created once, and free/busy), `google-drive` (search files,
   read metadata, export documents as text, read text files) and
   `web-search` over the Brave Search API (titles, URLs and snippets).
4. Format additions: a `mime` request body built by the same composer as
   SMTP, `decode_base64url` response paths, a `content_types` response
   guard, and the send-once `key` options `encoding: base32hex` and
   `conflict: confirms` (a 409 to a keyed repeat settles as sent,
   `send_intent_settled.source: key_conflict`).
5. IMAP `append_draft` and `save_attachments` ops prepare a mail for a
   person and save attachments under safe names.
6. A function marked `untrusted_output` returns text written outside the
   run; a binding that grants one without `untrusted: true` gets warning
   V187. Details in `docs/CONNECTORS.md`.

## Other changes

1. A decision posted to the review channel while the drive reads it no
   longer fails the run: a torn last line of `reviews.jsonl` reads as a
   decision not yet written, and a poster repairs a tail a crashed poster
   left.
2. An engine abort (a deadline, a superseded run) stops attempts in flight
   gracefully; `apb stop` stays immediate.
3. The baseline check's connector reads wait no longer than the time a
   run's deadline leaves.
4. The token shapes `ya29.`, `1//0` and `GOCSPX-` are scrubbed wherever
   credential-shaped values are detected.

## Behaviour changes

1. `github.list_issues` and `github.list_pulls` (connector 0.3.0) return up
   to 5 pages in one call, with `pages` and `more` in the result;
   `asana.list_tasks` (0.2.0) follows `next_page.offset` up to 5 pages.
   Each call still counts once against `max_calls`.
2. `imap.search_messages` and `imap.get_message` (connector 0.2.0) are
   marked `untrusted_output`, so a playbook that grants them without
   `untrusted: true` now gets warning V187.
3. A machine with a notify target now hears about every playbook with a
   `health:` block, since `health` is in the default transitions; a config
   that lists `on` explicitly hears about it only by adding `health`.
4. A dsh step on `nearai/<id>` has the cost basis `billed`, so the
   `billing:` section's `billed` policy (default `ask`) decides its start.
   apb owns the dsh route name `nearai`: in a spawn on it, your own
   `llm-pi-ai` routes are not mounted and your own `nearai` route is
   replaced.
5. `apb dashboard` fetches the public NEAR AI Cloud catalog once a day
   unless `cloud_models.near_ai_cloud.auto_refresh` is `false`.
6. A NEAR key value an agent prints is replaced before apb stores the
   reply.
7. A playbook with `deadline` leaves a sleeping deadline waker process
   while its run is paused or released.

## Compatibility

1. `policy.yaml`: an older apb reads a file with the new `runs:` section
   (`start_key_days`, `keep_days`, `keep_last`, `keep_failed_days`) or the
   new `health:` section as invalid. It then refuses launches through
   agent channels and creates no default notify subscription until it is
   updated.
2. `config.yaml`: an older apb refuses a config with the new
   `cloud_models:` section.
3. Connectors: an older apb cannot read the new manifests of `github`,
   `asana` and `imap`; after going back, reinstall them with that binary
   (`apb connector install <name> --force`).
4. Journal: one new event, `previous_success_set` (not a checkpoint, older
   readers skip it); additive fields `run_started.external_data`,
   `run_provenance.deadline`, `run_provenance.start_key`,
   `run_provenance.concurrency`, `run_resumed.deadline`,
   `attempt_started.cloud`, `attempt_finished.usage.priced_from`,
   `decision_made.privacy_class` and `connector_call.pages`, and the new
   value `key_conflict` of `send_intent_settled.source`.
5. New run guards `deadline` and `concurrency`: an older apb refuses to
   continue a run that uses them. A fresh launch by an older apb drops the
   unknown keys and runs without them, so it would start overlapping runs
   or runs without a deadline.
6. An external data run carries the mode suffix `+external`, so an older
   apb refuses to drive, resume or amend it, and its readers of earlier
   runs treat the origin `external_data` as unknown, which is not history.
7. A run an older apb started has no catalog row in its manifest and gets
   the dsh model row alone, as before.

# apb 0.19.0

This release adds the thirteenth official connector, twenty, for the Twenty open-source CRM, and two dashboard improvements: a cross-page project selector on the profiles page and a session cache for the agent and model lookups.

## The twenty connector

The connector exposes 41 functions over Twenty's REST API: typed CRUD for companies, people, opportunities, notes and tasks, note and task target links, duplicate search, generic record access that also serves custom objects by their plural REST name, restore, webhook management, and data-model metadata. Authentication is a bearer API key; an account carries the instance base URL and the key, and the same connector works for self-hosted instances and the cloud host. (#101)

Record deletions always send soft_delete=true because the vendor API's default is a permanent hard destroy, the opposite of what the Twenty UI does; the connector deliberately does not expose hard destroy, and restore_record undoes a soft delete. The one exception is delete_webhook, which the vendor only offers as a hard delete, and the docs say so. (#101)

Beyond 44 offline contract cases, the connector was smoke-tested live against a disposable Twenty v2.30.0 instance: healthcheck, filtered lists, full create, update, link, delete and restore cycles, duplicate search, generic record access and metadata, with every test record cleaned up afterwards. (#101)

## Dashboard

The project selector now also works on the profiles page and is shared across playbooks, runs and profiles, so a project picked on one page stays active on the others. Global-scope profiles remain visible for any selected project, since a global profile applies everywhere; only project-scope rows are filtered. (#101)

Opening a profile editor no longer re-runs agent detection on every visit: the dashboard caches the agent and model lookups per browser tab for one hour, deduplicating concurrent requests, while the project list stays live. (#101)

## apb 0.14.0: fan-out learns to wait, attempts learn to survive

This release is one PR built from three issues opened against the same shape of problem: a run that forked into parallel branches had no notion of waiting for all of them unless an author wrote `join:` by hand (#75), an agent session cut off mid-work lost everything it had not yet said out loud (#71), and supervised runs against real work surfaced six separate ways a finished agent's result could still be thrown away or misrouted by the engine around it (#74).

A node with more than one incoming edge and no explicit `join:` is no longer first-arrival by accident: when every source feeding it sits outside its own cycle, it now waits for all of them, exactly as if `join: all` had been written, while a merge point genuinely inside a loop keeps first-arrival semantics so loop bodies terminate the way they always did (#75). A join, implicit or explicit `all`, also stops waiting forever on a branch that will never arrive: a source no longer reachable from anything still active in the run counts as satisfied, so a conditional fork that only ever selects one of two branches reaches its join instead of deadlocking, and the write-off is journaled as its own `join_input_dead` event rather than hidden inside the scheduler. `join` values are validated instead of silently coerced: a value other than `all` or `any` is now an error (V36), mixing `all` and `any` across one node's incoming edges is a warning (V37), and a template that reads a node's output across un-joined parallel branches is a warning that names the missing barrier (V38).

The concurrent batch that already ran ready nodes in parallel for autonomous runs now runs in every mode, supervised included, capped by `max_parallel`: `defaults.max_parallel` in the playbook wins, then the cap persisted on the run's own config so a detached run resumed later keeps what it started with, then an engine default of four (#75). A supervised run executes its batch concurrently but supervises it serially, presenting failures one at a time in deterministic batch order at the batch tail, and a `join: any` satisfied by an earlier group cancels the branches still waiting for a slot. The batch path also reached parity with the long-standing sequential path: a batched node now hits the run's cache and records its captured artifacts exactly as a sequential node does, instead of always spawning fresh and reporting no artifacts. And a template that reads a node's output where that output renders empty now journals an observable anomaly, worded per reference and decided on the rendered value rather than on the source's status, so the canonical failure handler reading the failure it handles stays quiet while a step that succeeded with nothing to say does not (#74).

The attempt lifecycle stopped trusting the process exit code over the agent's own written verdict: when an agent writes a valid status file and the process then exits non-zero, times out, or is killed, the engine reads that file anyway and honors the verdict it holds, journaling the tail failure as a side note rather than discarding a finished deliverable, and a `{"status":"failure"}` file keeps the attempt failed while preserving the agent's own reported outputs instead of substituting raw CLI error text (#74). A new opt-in `require_verdict` on an `agent_task` node, or on `defaults`, makes writing that file mandatory rather than advisory: an attempt whose process ends without one is classified interrupted rather than silently succeeded, its partial output is preserved on the attempt, a retry is consumed, and the next attempt's prompt is told plainly that a previous attempt ended without recording a verdict and to check for work already done, commits and worktrees and files, before redoing any of it (#71). That interruption note is seeded from the journal, so it also reaches the first attempt of a node re-executed later by a supervisor retry, a resume, or a continue-from, instead of dying with the process that earned it.

A failure that looks like infrastructure noise, a dropped connection, a 5xx, a rate limit, now earns bounded automatic retries on the same executor out of a separate budget that never touches the node's own `max_retries`, with a backoff schedule that doubles as the budget and is tunable in one place through `APB_INFRA_BACKOFF_MS` (#71, #74). The budget is per fallback-chain step, so each step of a node's chain gets its own allowance. A failure that looks like an expired credential or a spend limit fails the attempt immediately and additionally skips every remaining chain step bound to the same agent, since a different agent may still succeed where an exhausted quota cannot, and the engine's own deadline kill is deliberately not read as infrastructure so no existing playbook silently gains extra attempts. An abort posted while a node waits out a backoff is observed within a poll tick rather than after the wait.

A run whose driver process died mid-attempt no longer reports that attempt as merely lost forever: the next time anything drives the run, an open attempt whose recorded process id is provably gone is closed out as interrupted and its node re-enters scheduling on its own (#71). The check is deliberately narrow, so an attempt with no recorded process id and an attempt whose process is alive, or whose liveness the probe could not settle, are both left exactly as they were.

Edge routing can finally read a structured verdict instead of only a status or a substring: a new `output_field` condition reads one named key out of a status file's own `outputs` object, so an agent that writes `{"status":"success","outputs":{"verdict":"failed"}}` routes the next step on that verdict directly, with every unreadable shape a plain non-match rather than an error (#74). A finish node composing a closing answer from a prompt that names no `{{run.context}}` or `{{nodes.*}}` placeholder now still sees the run's accumulated context, closing a gap where such a prompt composed its farewell from nothing at all (#74). And a node that declares expected output files has that declaration checked on every successful attempt rather than only when caching is enabled, with a declared glob that matched nothing, or a capture that failed outright, journaling a visible `deliverable_missing` warning instead of quietly reporting no artifacts (#74).

A supervisor's interrupt can now be aimed at one named node inside a concurrently running batch instead of only broadcasting to the whole run, so intervening in one runaway branch no longer takes down every branch running alongside it, and a sibling neither acknowledges nor consumes an interrupt addressed elsewhere (#75). The dashboard canvas learned the new condition too: an `output_field` exit is captioned by the field and the value it routes on rather than by the raw condition name.

Documentation caught up with what production profiles should already be doing. PROFILES.md now says plainly that a profile a run depends on should set `hermetic: true`, and where that flag stops (it is configuration hygiene, not a sandbox). HOWTO-authoring.md gained the join semantics above, the `max_parallel` cap, `require_verdict` and the interrupted status, declared deliverables, `outputs.extract` for output hygiene, the failure kinds and their retry budgets, the reaping boundaries, and advice for long-running orchestrator nodes to commit their progress early and often, so an interruption anywhere in this release's new resilience machinery costs the next attempt minutes of redone work rather than a whole phase (#71, #74).

Gates green throughout: fmt, clippy with warnings denied, the workspace test suite under both runners, doctests, code-ranker with no violations, `cargo clippy --release`, the frontend check, 385 frontend tests and the production build.

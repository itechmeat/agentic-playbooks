## apb 0.10.1: module boundaries

A structural release with no behavior change: the same CLI commands, MCP tools, HTTP routes, YAML schema, and event format as 0.10.0. What changed is where the code lives. Four modules had grown into the kind of file that has to be read whole before it can be edited safely, and the fix was to give each responsibility its own module rather than to keep appending.

`apb-server` went from a single 1600-line `lib.rs` holding 32 routes, 42 handlers and their request shapes to a thin router plus one module per resource (`routes/playbooks`, `runs`, `profiles`, `connectors`, `meta`), with the shared request state and project resolution in `state.rs`, the event stream in `ws.rs`, and the embedded frontend in `assets.rs`. The `?workspace=` query type moved out of the websocket module it happened to live in, since nearly every handler uses it.

`apb-mcp` gained the split its rmcp layer already had: the tool layer is now `tools/playbook`, `run`, `supervisor`, `trial`, `capture` and `meta`, over a shared error type. `apb-core`'s validator became `validate/` with one module per rule family (graph shape and routing, per-node fields, connector grants, template references), so a new V-code lands next to its relatives. `apb-engine`'s connector code moved from seven flat `connector_*.rs` files into a `connector/` module mirroring `apb-core`, and the call path itself now separates account selection, secret resolution, wire encoding and response mapping.

The scheduler's drive loop kept its sequencing but shed everything that was not sequencing: event-log folds, the live-channel observation, run entry points, the run listing, resume, the control-command scan, and the supervised wake park each moved to their own module. The scan and the park now return an explicit outcome instead of returning out of the middle of the loop from several places, which is what made both of them hard to follow.

Two duplications are gone. The wall-clock reading was copied twelve times across three crates under six different names, including one that lived in the engine's event-log module and was reached from three other crates just to read the time; it is now `apb_core::clock`. The symlink helper existed twice with four platform branches between them; it is now `apb_core::fsutil::symlink`, with the unsupported-platform case reported as an error kind callers map to their own domain error.

On the frontend, the API client is split into a shared fetch layer, a core module (playbooks, runs, profiles) and a connectors module, mirroring the server split. The five long-standing `svelte-check` warnings are fixed: three deliberate initial-value captures now say so with `untrack`, and the deprecated `baseUrl` is dropped from the TypeScript config.

One thing did change beyond structure. A review pass over the moved code found three places where a secret could leave the process it was resolved in: `Debug` on the IMAP and SMTP call structs printed the resolved password or token verbatim (they now print `[redacted]`), the connector prompt excluded env-backed account fields but not command-backed ones (both are excluded now, and the leak test covers both), and the capture tool's secret report echoed the first three characters of the candidate it was reporting as hidden (it now reports length only). A bare `.` is also no longer accepted as a workspace identifier.

Measured with code-ranker across the workspace, mean god-object risk fell by an order of magnitude and mean cyclomatic complexity by about a sixth, with no net growth in code. Every crate gate stayed green throughout: fmt, clippy with warnings denied in debug and release, the full test suite, the frontend check, tests and build.

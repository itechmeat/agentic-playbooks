# apb 0.16.0

This release introduces the playbook interview: a person describes a routine process in the chat they already use, and the agent turns the conversation into a draft playbook that carries an explicit goal with verifiable criteria. The playbook schema gains the goal as a first-class field, the validator enforces its completeness, and a new MCP tool delivers the interview guide to any connected agent.

## Goal on the playbook schema

A playbook may now declare `goal`: a statement in the owner's words plus a list of criteria, each with a check type, `manual` (default, a person confirms), `marker` (a marker string expected in the run result), or `script` (a check script path; execution is later engine work, the field records the contract). The field is fully additive: playbooks without a goal stay valid, parse identically, and never grow a `goal` key on rewrite, so existing digests are untouched. (#95)

New validator rule V41 enforces completeness when a goal is present: a non-empty statement, at least one criterion, a description on every criterion, a non-empty marker on marker checks, and script paths held to the same safety constraints node scripts already obey, through one shared policy helper. (#95)

The goal is visible where agents actually read: `playbook_get` summaries carry the full goal and catalog entries carry the goal statement, so an adopting agent sees the criteria it must never weaken. Both fields are additive and omitted for goal-less playbooks. (#95)

## The playbook interview

`docs/HOWTO-interview.md` is the agent-facing counterpart of the authoring guide: seven question blocks in plain employee language (task and trigger, data sources, steps as a story, a mandatory goal block, human gates, variables vs constants, exceptions), a playback-and-confirm gate before anything is built, honesty rules, and edge cases for resumed, duplicate, and too-vague interviews. The conversation itself always happens in the user's chat language. (#95)

The new read-only MCP tool `playbook_interview` serves the guide the same way `playbook_howto` serves the authoring guide. The server instructions and the `apb init` standing block now tell agents to offer a short interview when the user describes a process to automate. (#95)

## Documentation

The authoring guide documents the goal field, `docs/MCP.md` lists the new tool, and the process-recorder design spec and plan are preserved in the repository with deferred status as the future second entry point that will converge on the same goal-carrying draft. (#95)

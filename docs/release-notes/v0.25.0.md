# apb 0.25.0

A minor release about pausing a run on purpose (issue #200). An operator can
now pause any live run from the CLI, MCP or the dashboard, either letting the
running nodes finish or interrupting them, optionally until a set time. A
paused run holds no process and, by default, no lock; its clocks stop. A
provider quota error pauses the run by itself and resumes it once the quota
window has passed, and `apb resume --all` picks up what a reboot left
waiting.

## Operator pause

`apb pause <run>`, the MCP tool `run_pause` and the dashboard's Pause button
pause a run (`by: operator`, no supervisor token needed):

- **`--drain`** (the default): no new node starts, the running nodes finish
  and journal `node_finished`, then the run is paused. `apb resume` continues
  at the next node and never runs a finished node again.
- **`--now`**: the running nodes are interrupted (SIGTERM, a grace period,
  then SIGKILL; agent sessions keep their id). The attempt is journaled
  `interrupted`, spends no retry, and the node runs again on resume,
  continuing the agent's session where the agent can resume one. Only the
  first resume after the pause continues it; `--from-node` starts the node
  fresh.
- **`--reason`** is shown by `apb runs`, `apb wait` and the dashboard.
- **`--until`** takes an RFC 3339 time or a duration (`90m`, `2h`); a day
  the month does not have and a leap second are refused. A small
  detached waker resumes the run then; `apb resume` before that time is an
  early resume and says so.
- **`--keep-lock`** keeps the busy lock of the run's working tree while it is
  paused, so no other run can touch the tree. Without it the lock is released
  and another run can use the tree; `apb doctor` lists kept locks and
  `apb stop` of the run releases them.

Pausing a paused run updates its reason and `until`. Open reviews, questions
and host tasks stay open across a pause.

## Frozen clocks

The time a run spends paused does not count: node and host-task deadlines,
wait-node timers, question timeouts, the eval deadline, `expected_duration`
comparisons and the run and node durations in `apb stats`, `run_report` and
the retro all leave it out. A playbook can read
`{{run.active_elapsed_seconds}}` for a budget of its own.

## Host tasks across a pause

Pausing a host-mode run does not expire or supersede its open host tasks, and
their deadlines are frozen with the run. A reply sent with `run_task_submit`
while the run is paused is stored and applied on resume. `run_wait` on a
paused run returns `reason: stopped` with the `pause` object and the open
tasks in `pending_tasks`.

## Quota auto-pause

A provider quota or rate limit (HTTP 429, `too many requests`, `rate limit`,
`FreeUsageLimitError`, `credit usage limit`) is now its own failure kind,
`quota`. The node tries a profile fallback first, then the infrastructure
retries, unless a `Retry-After` outlasts the next retry step. After that the
run pauses (`by: engine`, `reason: quota (<agent>/<model>)`) until the
`Retry-After` time (capped at 7 days), or on a 15 min, 30 min, then 1 h
schedule. The paused
attempt spends no retry.

When `until` passes, the waker first sends one minimal probe call to the same
agent and model. A probe that hits the quota again re-pauses the run at the
next step; any other outcome resumes it. Probe outcomes are journaled as
`quota_probe` supervisor actions. After 6 quota pauses of the same node
without a successful attempt, the node fails as `quota exhausted`. Host tasks
and script nodes are not affected.

## Resuming

- `apb resume --all` resumes the runs of a workspace that a lost driver or a
  passed `until` left waiting: runs reading `running` with no live driver,
  and paused runs whose `until` has passed (a due quota pause is probed
  first). A driverless run that cannot be resumed is journaled
  `paused (driverless)`, so `apb runs` no longer shows it as `running`.
  One whose working tree another run holds busy is left as it is for a
  later pass.
  `docs/DEPLOYMENT.md` has a systemd user unit that runs it at boot.
- A resume is refused while another live run holds the busy lock of the
  run's working tree: `apb resume` exits 2 with `workdir busy`, `run_resume`
  returns the conflict, the dashboard answers 409 and shows an error, and the
  run stays paused. A waker whose `until` arrives while the tree is busy
  waits until the lock frees.

## Surfaces

- `apb runs`, `run_status`, `run_wait` and `runs_list` carry a `pause`
  object (reason, by, mode, since, until, keep_lock, pausing); `apb runs`
  prints `paused (reason, by, since, until)` or `pausing (...)` next to the
  status.
- `apb wait` exits 4 on a paused run and prints the reason, who paused it
  and when it resumes.
- MCP: the new `run_pause` tool; `run_resume` reports an early resume with
  `resumed_early` and `pause_until`.
- Dashboard: a pause marker in the run list, and in the run view a pause
  strip with the reason and times, a Pause form (drain or now, reason, until,
  keep the lock), a pausing state while running nodes drain, and a Resume
  button for a paused or driverless run that goes through the same run gate
  and irreversible-effects consent as `run_resume`.

## Fixes

A detached driver waiting on a host task no longer polls forever once its
run directory has been deleted; the wait ends and the driver exits.

The wake-up path of a timed pause is hardened: the probe and the resume
make the same checks as `apb resume` before anything of the run executes,
and a pause, resume or stop that arrives while a waker is resuming the run
is no longer overwritten.

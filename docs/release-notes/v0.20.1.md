# apb 0.20.1

A patch release with one connector fix and one dependency bump.

## The atrip post-booking ancillary endpoints accept their second identifier

0.20.0 taught `post_booking_ancillary_search` and `post_booking_ancillary_order` to render their order identifiers into the request body, which made the `ticketOrderNo` path work. The vendor accepts a second identifier that the connector still could not send: `airlinePNR` plus `carrier`. Neither field was in the body template, so a caller holding only the airline record locator could not reach the endpoints at all, and a call carrying no identifier came back as `702 airlinePNR and carrier are required`. Both fields are now declared, under the same `oneOf` convention `refund` already uses, so exactly one of the two identifiers is required. (#117)

Two details are now recorded in the manifest rather than learned by debugging: the `airlinePNR` these endpoints want is `queryOrderDetails`' `airlineBookings[].airlinePnr` and not the Atlas order `pnrCode` — passing the `pnrCode` answers `704 Query parameters don't match order records` — and an empty or null `ancillaryProductElements` is a normal `status` 0 outcome meaning the fare offers no post-ticketing baggage, not an error. (#117)

`post_booking_ancillary_order`'s `passengers` schema also described a shape the endpoint does not take. It required `name`, `type` and `gender`; the endpoint expects `name` plus `passengerType` and the chosen `ancillaries`, each carrying `productCode`, `segmentIndex` and `quantity`. The optional context both endpoints accept is declared too: `paymentMethod`, `fromSegments` and `retSegments` on search, and the `payment` instruction on order. (#117)

The search path was confirmed against a live AtripTech sandbox on both identifiers. The order endpoint is effectful, so its corrected schema follows the vendor contract without a live purchase behind it. (#117)

## Dependency

`h2` moves to 0.4.16, clearing RUSTSEC-2026-0258: the crate accepted and queued empty DATA frames without limit, so a stream that was not actively drained could grow memory unboundedly or panic on length overflow. Low severity, and `h2` is only a transitive dependency here, reached through `hyper`. (#118)

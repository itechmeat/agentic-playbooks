# apb 0.25.1

A patch release. `apb resume --from-node` no longer starts a join whose
other branch the resume brings back to life, and a supervisor retry of a
failed parallel branch no longer does either. (#203)

## Joins wait for a re-run branch

A run failed in one branch of a fork, so its join wrote that branch off
(`join_input_dead`) while the other branch had already delivered. Resuming
the run from the failed node then started the join in the same moment as
the re-run node: the join was weighed against the old pass, in which the
re-run node was still failed and routed away. In the field case the join
ran, and so did the import step after it, before the revived branch had
produced anything. In a second shape, where the join had already run on the
first pass, the run ended `succeeded` through the join's old route into its
finish node, without running the join again on the new input.

A drive that executes a node again now treats that node and every node only
downstream of it as not yet run when it rebuilds the branches it has to
finish:

- a join fed by the re-run node's branch waits until that branch arrives,
  then runs with the normal readiness check; if the branch dies again (the
  node fails again, or routes elsewhere), the join is weighed again and
  journals a fresh `join_input_dead`, exactly as in a first pass;
- a node that already ran in the old pass on an input from outside the
  re-run (a `join: any`, a merge inside a cycle) is not run again at once on
  that old input; it runs when the re-run branch delivers into it;
- an old route of a downstream node is not taken again: the run reaches its
  finish node through the join's new execution;
- nodes upstream of the re-run node keep their state, and inside a loop the
  nodes that lead back into it keep their routing and stop the revival: a
  sibling branch that never started is still waited for, and one that
  already completed is not re-run before the loop comes back to it.

This applies to `apb resume --from-node` and `run_resume` with `from_node`,
to the restart of an interrupted node, and to a supervisor's
`supervisor_node_retry` or `supervisor_run_continue_from` after a failed
member of a parallel batch.

## `join_input_revived`

The journal records the revival: one `join_input_revived` event per join
whose earlier write-off no longer holds, with `node` (the join), `sources`
(the inputs it waits for again) and `from_node` (the re-run node). It is
written before the re-run node starts. The dashboard's run journal now shows
a note for it and for `join_input_dead`. Older apb versions skip the event,
which carries no state of its own, as long as a checkpoint follows it (the
re-run node's finish, or a pause). A run whose driver was killed in between,
mid re-run, must be resumed with 0.25.1 or newer.

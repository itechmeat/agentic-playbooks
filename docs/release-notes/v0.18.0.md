# apb 0.18.0

This release adds the twelfth official connector: atrip, covering AtripTech's Atlas flight-booking API.

## The atrip connector

The connector exposes the full documented Atlas surface as 28 functions: flight search, fare verification and offer-based pricing, order creation, payment, order status queries, seat and baggage ancillaries before and after ticketing, void, refund, PNR claim and live PNR extraction, order regeneration, account balance, bulk route export, notification-mail queries, webhook registration, and incident lookup. Every endpoint and field comes from the vendor's published documentation; endpoints whose request bodies the vendor does not fully specify carry deliberately loose schemas and say so. (#99)

Eight functions are marked effectful because they move money or change a real booking: order, pay, void, refund, stop_ticket, regenerate_order, pnr_claim, and post_booking_ancillary_order. The payment call documents that the vendor offers no idempotency key, so a duplicate attempt while a prior payment is in flight risks a double charge and must never be retried blindly. (#99)

Authentication uses the Atlas header pair: the client secret travels through the connector's auth block and the client id as an account field, so the secret never appears outside the auth template. Accounts carry per-tenant base and search URLs; the sandbox host serves both until production URLs are issued in the vendor portal. Success for most calls is a status field inside the JSON body rather than the HTTP status, and the per-call conventions are documented on each function. (#99)

The folder ships with 28 offline contract cases, the standard storefront and setup documents, and a new subsection in the connectors guide. (#99)

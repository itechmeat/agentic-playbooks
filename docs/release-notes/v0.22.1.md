# apb 0.22.1

A patch release with two fixes: a projects registry an older or newer apb cannot parse is never overwritten, and a loop edge that points straight back at its own node loops instead of failing the run. It also folds in a set of smaller fixes to the decision-model layer, `apb doctor`, the test suite and the documentation. The projects registry now carries `schema_version: 2`; 0.20.x and 0.21.x still read it, through the `name` and `playbook_count` fields it keeps writing for them.

## The projects registry survives an older dashboard

When two apb builds share one config directory, an older build that could not parse `projects.json` treated it as empty and wrote the empty registry back, and every registered workspace disappeared from the dashboard. The ordinary way to get there was an in-place upgrade from 0.20.x or 0.21.x to 0.22.0 with the dashboard service still running on the old binary: 0.22.0 had dropped the per-entry `name` field that the older reader requires, while `schema_version` stayed at `1`. (#177)

A registry file that exists but does not parse, cannot be read, or carries a `schema_version` newer than the binary knows is now never written. Listings and lookups answer from a read-only view of it, every writer refuses (`apb projects remove` exits with the reason), and the reason is logged once per process. Fields this build does not know, on the file and on each entry, are kept on every write. Entries carry `name` and `playbook_count` again, computed at registration as 0.20.x and 0.21.x did, and entries a 0.22.0 build left without `name` are filled in, so a still-running older dashboard keeps parsing the file. `schema_version` is now `2`: a version-1 file is read as it is and upgraded once on its next access, and a later format change will make this build refuse to write rather than downgrade. (#177)

The older binaries themselves cannot be fixed, so the damage they can still do depends on the file they find. Upgrading from 0.20.x or 0.21.x to 0.22.0 with the dashboard running can empty the registry; upgrading straight to 0.22.1 cannot, because every file 0.22.1 writes stays readable by the old dashboard. A registry emptied by an earlier upgrade stays empty: run any registering command (for example `apb runs`) inside each workspace to register it again. Stopping or restarting the dashboard when the binary is replaced remains the simplest habit. `apb doctor` now reads the running dashboard's version from `/api/health` and warns when it differs from the binary, which is exactly the state in which the damage happened. (#177)

## A self-loop edge loops

A node whose loop edge points straight back at itself (`review -> review`, bounded by `max_traversals`) failed the run on its first pass with "has no outgoing edge and is not finish", although the validator accepted it and a `fallback` edge was wired. The frontier dropped the node it had just finished, so the selected self-edge led nowhere. (#171)

A selected self-edge now re-enters its node like any other loop edge: each pass is a counted `edge_traversed review -> review`, the node runs again, and once the cap is spent the run takes the fallback edge. A self-edge whose condition stops matching earlier ends the loop there. Resume after the looping node and self-loops inside parallel branches behave the same, and a `judge` self-edge gets its own answer for every execution. `docs/HOWTO-authoring.md` ("Bounded loops") shows the pattern. (#171)

## Also fixed

- The review auto-decision of a gated run weighs the sub-playbook versions the run's gate pinned, the versions it will execute, instead of whatever version is current when the gate is reached. A child re-versioned mid-run no longer changes the verdict in either direction. (#178)
- A `playbook_catalog(query)` for another workspace applies the stricter of the calling project's and the target project's decision settings, so a project that switched catalog ranking off is never ranked on behalf of another one. (#178)
- `apb decisions report` and `apb decisions replay` read only run directories apb created on this machine (their origin stamp verifies), so a journal that came with a repository is neither counted nor replayed. The number skipped is printed on stderr. (#178)
- The catalog-ranking daily-cap lock lives as long as the provider chain can legitimately hold it (`timeout_ms` times the number of providers plus ten seconds) instead of a fixed minute, and an abandoned lock is broken with a `stale_lock_broken` note in `decisions.jsonl`. (#178)
- `apb doctor` checks each decision provider with one request that costs nothing, sent with its key to its own base URL within `timeout_ms`, and reports the HTTP status and latency or the timeout. A connect alone had reported a provider as reachable while it hung every request. Providers with a command-produced key keep the connect check, labelled "connect only". (#178)
- A detached driver re-exec'd from a binary that was just rewritten waits out a short "text file busy" window instead of failing to start. (#178)
- Five tests that failed under a loaded host no longer depend on timing: they wait for the state they need (a node held until the test releases it, a pending review, a listener's own readiness banner, the dashboard's own port claim) instead of racing it. (#178)
- `docs/DECISIONS.md` names the release each use shipped in, `CHANGELOG.md` points to `docs/release-notes/`, and the README states the current release line. (#178)

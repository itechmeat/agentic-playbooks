# apb 0.24.1

A patch release that fixes the macOS release gate of 0.24.0, stops `apb eval` from killing the processes of a concurrent eval, and adds a macOS test leg to pull-request CI.

## The macOS release gate passes again

The 0.24.0 tag did not publish: both macOS build legs failed their test gate on one eval test, `a_kept_tree_survives_the_scratch_cleanup`. Its stub agent started a detached helper through the util-linux `setsid` binary, which macOS does not ship, so the helper never started and the test failed reading the pid file the helper writes. The test now detaches the helper through Perl's `POSIX::setsid`, available on both macOS and Linux, and sets the helper's argv[0] without bash's `exec -a`. Its assertions are unchanged. The other tests added in 0.24.0 were audited for Linux-only assumptions; the only other ones, the `/proc`-based cleanup of detached helpers and its tests, were already Linux-only by design. (#181)

## An eval no longer kills the agents of another eval

After a repetition ends, `apb eval` on Linux kills the helpers its agent left behind, recognising them by the run's id in their environment. A run id is `<playbook>-<ms>` and unique only within one working tree, while every repetition runs in a tree of its own, so two evals (or two repetitions) of the same playbook started in the same millisecond shared an id, and the one that finished first killed the other's still-running agent. The cleanup now also requires the process's run directory (`APB_RUN_DIR`, which the engine sets next to `APB_RUN_ID` for every agent and script step) to lie inside the repetition being cleaned up. The eval tests running in parallel hit this intermittently. (#181)

## macOS tests run on every pull request

CI gains a `test-macos` job that runs the same `cargo nextest run --profile ci --workspace` and doctests as the release gate, on `macos-latest`. A Linux-only assumption in a test now fails the pull request instead of the release tag. Web checks, cargo deny, fmt and clippy stay on the Linux job. (#181)

# apb 0.24.1

A patch release that fixes the macOS release gate of 0.24.0, stops `apb eval` from killing the processes of a concurrent eval, adds a macOS test leg to pull-request CI, and labels the model hint of host tasks so a fallback's declared model no longer reads as the model that ran.

## The macOS release gate passes again

The 0.24.0 tag did not publish: both macOS build legs failed their test gate on one eval test, `a_kept_tree_survives_the_scratch_cleanup`. Its stub agent started a detached helper through the util-linux `setsid` binary, which macOS does not ship, so the helper never started and the test failed reading the pid file the helper writes. The test now detaches the helper through Perl's `POSIX::setsid`, available on both macOS and Linux, and sets the helper's argv[0] without bash's `exec -a`. Its assertions are unchanged. The other tests added in 0.24.0 were audited for Linux-only assumptions; the only other ones, the `/proc`-based cleanup of detached helpers and its tests, were already Linux-only by design. (#181)

## An eval no longer kills the agents of another eval

After a repetition ends, `apb eval` on Linux kills the helpers its agent left behind, recognising them by the run's id in their environment. A run id is `<playbook>-<ms>` and unique only within one working tree, while every repetition runs in a tree of its own, so two evals (or two repetitions) of the same playbook started in the same millisecond shared an id, and the one that finished first killed the other's still-running agent. The cleanup now also requires the process's run directory (`APB_RUN_DIR`, which the engine sets next to `APB_RUN_ID` for every agent and script step) to lie inside the repetition being cleaned up. The eval tests running in parallel hit this intermittently. (#181)

## macOS tests run on every pull request

CI gains a `test-macos` job that runs the same `cargo nextest run --profile ci --workspace` and doctests as the release gate, on `macos-latest`. A Linux-only assumption in a test now fails the pull request instead of the release tag. Web checks, cargo deny, fmt and clippy stay on the Linux job. (#181)

## Host task hints say where they come from

In host execution mode the profile's executor chain still engages, and each step is a new host task: an expired deadline or an unanswered question advances to the next fallback entry or routed tier at once, while a `failed` submission first spends the node's retries on the same step. Such a task carried the step's declared model as a bare `model_hint`, so `apb tasks` printed `model hint <model>` and read as if apb had switched the work to that model, while the host always picks its own. Every host task and its `host_task_requested` event now carry `hint_source` (`primary`, `fallback` with its index and count, `tier`, or `host_fallback` for the host step of a `cli` run whose CLIs could not start, each with the profile) and, on the first task of a later chain step, `fallback_of` (the attempt that closed the previous step and how: `failed`, `expired`, `question_timeout`, ...). The engine carries that reason from one step to the next in memory and renders the label once, as `hint_note` on the pending task and on the `host_task_requested` event, so the CLI, MCP, the journal and the dashboard show the same line. The journal says why a fallback task exists while it is still pending, not only once `fallback_triggered` lands at the node's end. Pending tasks add `hint_note`, one English line such as `model hint M (fallback 1 of 1 declared by profile P after attempt 1 failed; the host picks its own model)`, which `apb tasks` prints on the task's header line and the dashboard shows under the badge; the primary step reads `primary executor of profile P (no model hint; the host picks its own model)`. With tier routing to a tier above the profile's executor, that tier now carries the hint and the executor behind it none, instead of the reverse. The new fields are additive, and the structured ones decode leniently in the journal and in a task's `task.json`, so older journals and older readers are unaffected.

## A host can report the model it ran on

`run_task_submit` takes an optional `model` and `apb tasks submit` a `--model`: the model the subagent actually ran on, when the host knows it. It is trimmed, cut to 128 characters and refused when it holds a control character, then journaled on `host_task_submitted.model` as reported and shown in the dashboard's journal; apb never infers it. The `run_wait` and `run_task_submit` descriptions and the host-mode docs (`docs/HOST-INTEGRATION.md`, `docs/PROFILES.md`, `docs/HOWTO-authoring.md`, `docs/MCP.md`) now say that `model_hint` is a profile declaration, not a measured fact.
